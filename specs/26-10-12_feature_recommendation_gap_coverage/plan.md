# 작업 순서

선행 조건: 사용자가 이 문서의 [미확정 사항](./decisions.md)을 검토하고 구현 시작을 승인한다. 승인 전에는 코드를 바꾸지 않는다.

1. [ ] RGC-01 기준선: 임시 측정 테스트를 저장소 테스트로 옮겨 일상 조합 10개·전체 선택·미지원 빈도를 고정한다. 로드맵의 1,215개와 실측 1,218개 차이 원인을 찾는다.
2. [ ] RGC-02 분류: 빈도 상위 미지원 이름(최소 상위 100개)을 (가)(나)(다)로 분류하고 근거 레시피를 남긴다. 결과표를 `decisions.md`에 정리해 사용자 승인을 받는다.
3. [ ] RGC-03 실패 테스트 먼저: 승인된 동의어 매핑과 새 재료의 기대 결과를 테스트로 작성하고 실패를 확인한다.
4. [ ] RGC-03~04 구현: 동의어 표·선택 재료 추가, 필요한 경우 생성기 재실행. 원문 분량·순서·출처 불변을 테스트로 확인한다.
5. [ ] RGC-05 전후 비교: 기준선과 같은 방법으로 재측정해 `validation.md`에 표로 기록한다. 준비 완료가 늘어난 레시피의 원문을 표본 점검한다.
6. [ ] RGC-06 전체 검증: `npm test`, `npm run test:scripts`, `npm run lint`, `npm run build`, 기본/출시 산출물의 광고 ID 검사.
7. [ ] 브라우저 확인: 320×640과 393px에서 칩 목록·선택 요약·추천 결과를 확인한다.
8. [ ] RGC-07 새 번들 준비(사용자 승인 후): 업로드·테스트 푸시는 별도 승인. 기기 QA는 사용자 결과가 필요하다.
