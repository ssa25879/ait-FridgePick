# 요구사항: 식품안전나라 레시피 CSV 카탈로그

## 목적

기존 20개 레시피만으로 추천 조합이 부족할 수 있으므로, 출처와 데이터 이용 조건을 확인한 레시피를 기존 앱의 로컬 추천 흐름에 추가한다.

## 범위

### 포함

- 식품안전나라 조리식품의 레시피 DB CSV를 로컬에서 검토하고 정규화한다.
- 원본 CSV의 행 수, 열, 인코딩, 필수 필드, 중복 및 데이터 품질을 기록한다.
- 재료명을 확장된 카탈로그의 재료 ID에 명시적인 별칭 규칙으로 연결하고, 화면에서 선택할 수 있게 한다.
- 앱에서 정적 데이터로 쓸 수 있는 레시피만 생성한다.
- 앱인토스 WebView 미니앱의 번들·실행 흐름에서 정적 데이터가 정상 동작하는지 검증한다.
- 원본 레코드 식별자, 출처, 제공된 경우 데이터 기준일 및 확인된 이용 조건을 추적한다. 기준일이 입력 파일에서 확인되지 않으면 미확인으로 기록한다.
- 기존 레시피와 추천 계산·앱 화면이 함께 동작하는지 검증한다.

### 제외

- 앱 런타임에서 외부 API 호출 또는 CSV 다운로드
- 인증키를 앱 번들, 소스 코드, Git, Vite 클라이언트 환경 변수 또는 로그에 보관
- 서버, 데이터베이스, 자동 정기 수집 파이프라인 추가
- 식품안전나라 원본 CSV를 저장소에 커밋
- 권리 범위가 확인되지 않은 이미지 등 제3자 자산을 앱에 복사하거나 재배포
- 근거 없는 유사어 추론으로 재료 ID 자동 지정
- 이번 작업에서 재료 선택 UI나 기존 추천 임계값을 변경

## 요구사항

| ID | 요구사항 | 완료 조건 |
| --- | --- | --- |
| FSK-01 | 출처의 재사용 조건을 확인한다. | 앱 내 정적 제공, 데이터 가공, 필요한 출처 표시가 허용되는지 근거와 함께 기록한다. 불명확하거나 허용되지 않으면 앱 배포용 데이터 생성을 중단한다. |
| FSK-02 | 인증키와 원본 파일을 보호한다. | 키는 대화·소스·앱 번들·저장소·로그에 나타나지 않는다. 원본 CSV는 Git 추적 대상이 아니다. |
| FSK-03 | 실제 CSV 구조를 검증한다. | 인코딩, 헤더, 행 수, 필수 필드, 원본 식별자, 중복을 기록하고 파싱 결과를 대조한다. |
| FSK-04 | 재료를 보수적으로 정규화한다. | 명시적으로 등록된 이름·별칭만 카탈로그 ID에 연결한다. 매핑률이 60% 미만이거나 매핑된 필수 재료가 없는 레시피는 사유와 함께 제외한다. 나머지 미지원 필수 재료는 데이터에 별도로 보존하고 추천률 및 결과 화면에 반영한다. |
| FSK-05 | 원본과 앱 데이터 사이 추적성을 둔다. | 앱에 포함하는 레시피는 고유 ID와 원본 레코드 ID를 추적할 수 있고, 허용된 출처 표시가 제공된다. 데이터 기준일이 제공되지 않으면 미확인으로 기록하며 날짜를 추정하지 않는다. |
| FSK-06 | 기존 카탈로그와 결합한다. | 기존 수기 레시피는 보존하며 새 레시피와 ID가 충돌하지 않는다. 매핑된 필수·선택 재료 ID는 모두 재료 카탈로그에 존재하고, 미지원 필수 재료는 별도 필드로 추적한다. |
| FSK-07 | 추천 데이터의 효과를 확인한다. | CSV 총 행 수, 포함·제외 수와 제외 사유, 대표 재료 선택 묶음의 추천 후보 없음 비율을 기존 카탈로그 기준과 비교해 기록한다. |
| FSK-08 | 앱인토스 품질 기준을 확인한다. | 테스트, lint, `npm run build`의 TypeScript·Vite·AIT 빌드 결과를 기록하고, AIT DevTools 320×640 CSS px 및 가능한 경우 Toss 테스트 환경에서 재료 선택부터 결과까지 확인한다. 정적 카탈로그가 추가된 번들 크기도 기준 빌드와 비교해 기록한다. |

## 완료 조건

- 공식 출처의 데이터 재사용·재배포 조건과 앱 내 출처 표시 방식을 확인했다. CSV에 데이터 기준일이 없어 이를 미확인으로 기록했다.
- 인증키와 원본 CSV가 저장소에 들어가지 않는다.
- CSV 구조와 전체 처리 건수를 설명할 수 있으며, 제외 사유가 추적된다.
- 포함 레시피는 앱 레시피 모델·재료 ID 규칙을 충족한다. 미지원 필수 재료를 숨기지 않고 매칭률과 결과 화면에서 추적한다.
- 기존 카탈로그를 보존하고 정규화 결과가 추천 후보 증가에 미치는 효과를 비교했다.
- 요구사항별 자동·수동 검증 결과를 기록했다.
- 라이선스 조건 또는 데이터 품질이 충족되지 않으면 배포 가능한 데이터가 추가되지 않고, 그 사유와 대안을 기록한다.

## 완료 수 기준

포함 가능한 레시피 수의 목표치는 실제 CSV를 분석한 뒤 정한다. 현재 확인되지 않은 행 수나 정규화 성공률을 미리 완료 기준으로 가정하지 않는다. 다만 기존 대표 입력에서 추천 후보 없음 비율이 개선되지 않으면, 데이터 추가만으로 문제가 해결되었다고 보고하지 않는다.
