# 개발 계획: 추천 결과 흐름과 메뉴 후보 계산

## 목표

로드맵 1단계의 남은 두 항목과 4·5·6단계를 이어서 완료한다.

## 변경 파일 후보

- `src/utils/recommendRecipe.ts`: 후보 판정, 결과 계산, 무작위 선택
- `src/utils/recommendRecipe.test.ts`: 추천 규칙과 경계 테스트
- `src/pages/ResultPage.tsx`: 상세 추천 결과, 빈 상태와 홈 복귀 화면
- `src/pages/IngredientPage.tsx`: 메뉴 추천 시작 입력 연결
- `src/App.tsx`: 세 화면 상태, 추천 결과와 후보 소유
- `src/App.test.tsx`: 추천·다시 뽑기·홈 왕복·빈 결과 흐름
- `src/App.css`: 추천 버튼과 결과 화면의 좁은 폭 레이아웃
- 기존 `src/index.css`의 `env(safe-area-inset-*)` 안전 여백 규칙 확인
- `apps-in-toss.config.ts`: 중립 브랜드 기본 색상
- `AGENTS.md`, `CLAUDE.md`, `docs/design-guide.md`: TDS 디자인 가이드 주입
- `specs/roadmap.md`: 완료 기준과 후속 단계 상태
- `specs/26-09-29_feature_result_navigation_recommendation/*`: 기능 문서

## 전역 제약

- 후보 기준은 필수 재료 매칭률 60% 이상이며 경계값을 포함한다.
- 선택 재료는 메모리 상태로 유지하고 결과→홈 이동은 초기화하지 않는다.
- 후보 계산은 필수 재료만 사용하며 optional 재료는 제외한다.
- 결과 화면에 메뉴명, 매칭률, 보유·부족 재료, 조리 단계, 재추첨, 초기화와 홈 복귀를 제공한다.
- 빈 재료·후보 없음·단일 후보·여러 후보 흐름을 구분한다.
- 라이브러리와 의존성 버전은 변경하지 않는다.

## 완료 정의

- 로드맵 1단계 남은 화면 상태 및 결과→홈 복귀 항목이 검증된다.
- 4단계 추천 데이터, 60% 후보 기준, 재추첨과 빈 결과가 테스트된다.
- 5·6단계 상세 결과 정보·초기화·빈 상태 흐름이 구현되고 자동 검증된다.
- 자동 검증, 빌드, 좁은 모바일 화면 확인과 심층 리뷰가 끝난다.
