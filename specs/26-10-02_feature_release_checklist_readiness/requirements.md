# 요구사항: 비게임 출시 체크리스트 대응 및 출시 준비

## 목적

비게임 출시 가이드에서 확인된 공통 요구를 충족하고, 광고·플랫폼 동작은 지원되는 토스 앱 환경에서 증거를 남긴다. 이 문서는 계획이며 아직 코드 수정이나 실기기 검증을 완료했다는 뜻이 아니다.

## 범위와 제외

### 포함

- 비게임 사용자 식별키 획득 및 필요한 사용자별 상태의 재방문 복원
- 지도 외 확대·축소 제스처 제한
- 배너 광고가 스크롤 가능하고 허용된 화면에만 노출되는지 판단
- 광고와 주요 CTA의 분리, SDK 기본 광고 UI·동작 유지
- 네비게이션·뒤로가기·스킴·반응성·세이프 에어리어 실기기 검증
- 테스트 광고와 실제 광고 ID의 분리 및 출시 선행조건 추적

### 제외

- 로그인·계정·서버·결제·공유 리워드·새 권한 흐름
- 실제 광고 ID를 이용한 개발 테스트
- 명시적 사용자 요청 전 콘솔 검수 제출, 라이브 배포 또는 출시
- 배너를 보여주기 위한 빈 공간·불필요한 콘텐츠 추가

## 요구사항

| ID | 요구사항 | 완료 조건 |
| --- | --- | --- |
| RCR-01 | 비게임 사용자 식별키를 확인한다. | 앱 시작 흐름에서 공식 `User.getAnonymousKey()`를 호출하고 `{ type: "HASH", hash }` 결과 또는 지원 환경의 오류를 안전하게 처리한다. 토스 앱에서 실제 응답을 확인한다. |
| RCR-02 | 필요한 사용자 상태를 재방문 후 복원한다. | 현재 재료 선택, 매칭률, 난이도처럼 계속할 때 필요한 상태만 식별키에 귀속해 저장하고 앱을 종료·재진입해 복원한다. `처음부터`는 기존 초기화 의미를 유지한다. 저장소 읽기·쓰기 오류가 있어도 현재 세션의 핵심 사용 흐름은 유지한다. |
| RCR-03 | 식별키와 저장 데이터 범위를 제한한다. | 새 로그인·서버·개인정보 수집을 추가하지 않는다. 식별키는 미니앱 내부 상태 관리 용도로만 쓰며 필요한 최소 상태만 보관한다. |
| RCR-04 | 불필요한 확대·축소를 막는다. | 지도 기능이 없으므로 핀치 확대·축소가 출시 대상 토스 앱에서 동작하지 않고, 핵심 터치 조작은 정상 동작한다. |
| RCR-05 | 배너 노출 화면이 광고 정책에 맞는다. | 배너는 실제로 스크롤 가능한 비일시적 화면에만 부착된다. 홈이 이 조건을 만족하지 않거나 인트로 화면으로 판정되면 추가 배너 노출 전 사용자와 위치를 재결정한다. 광고용 빈 여백은 추가하지 않는다. |
| RCR-06 | 광고와 사용자 조작을 명확히 분리한다. | 공식 SDK 배너 UI와 “Ad” 표기를 변경하지 않고, CTA와의 간격·터치 영역을 시각 확인해 오클릭 우려가 없다. |
| RCR-07 | 플랫폼 이동과 주요 동작이 정상이다. | 토스 네비게이션의 닫기·뒤로가기·더보기, 첫 화면 종료, Android 시스템 백버튼, 지원 스킴 진입 후 뒤로가기를 실제 기기에서 확인한다. |
| RCR-08 | 반응성 및 화면 안정성을 확인한다. | 화면 진입·터치·스크롤 반응이 2초 이내이며, 320×640 및 대표 기기에서 가로 넘침·CTA/광고/safe area 겹침이 없다. 비정상적인 메모리·네트워크 급증도 관찰되지 않는다. |
| RCR-09 | 광고 표시와 광고 타입별 동작을 점검한다. | 배너는 적절한 위치의 스크롤 화면에만 표시되고 오클릭·예상치 못한 노출이 없다. 다른 광고 타입이 연결된 경우 사전 로딩, 음악 일시정지/복귀, 광고 종료 후 복귀, 리워드 지급까지 검증한다. 테스트 ID와 승인 후 실제 광고 확인을 분리한다. |
| RCR-10 | 외부 출시 선행조건을 추적한다. | 워크스페이스 대표관리자의 제휴 약관 동의, 최초 앱·번들 검수, 라이브 전환을 체크리스트에 남기며 권한 없는 외부 작업은 수행하지 않는다. |
| RCR-11 | 보안·렌더링·통신 규칙을 점검한다. | 외부 전달 코드 실행과 외부 콘텐츠 렌더/이동을 사용하지 않고 CSR/SSG만 사용한다. API/웹소켓은 HTTPS/WSS를 쓰며 민감 데이터 저장·개인정보 전송을 확인한다. 미사용 항목은 코드·설정 근거와 함께 해당 없음으로 기록한다. |
| RCR-12 | 접속·내비게이션·기본 서비스 UX를 점검한다. | 앱 정보에 등록한 기능·스킴과 앱 동작이 일치하고, 플랫폼 네비게이션·뒤로가기·닫기·더보기·종료 경로·외부 링크·공유 `intoss://`가 정상이다. 내비게이션에 앱 이름/로고를 표시한다면 등록된 국문 이름·브랜드 로고를 쓰고 파트너 자체 로고는 금지하며, 자체 뒤로가기 중복 및 기능 버튼 1개 초과를 금지한다. 라이트 테마, UI 동작, 문구·콘텐츠, 예측 가능한 CTA, 자동/강제 바텀시트 금지, 자체 서비스/앱 설치 유도 금지를 확인한다. |
| RCR-13 | 조건부 기능·권한 체크리스트를 분류한다. | 토스 로그인, 인앱 결제, 토스페이, 공유 리워드, 위치·알림 권한, 음악 연동 및 배너 외 광고 타입이 연결됐는지 코드·콘솔로 확인한다. 미연결은 근거와 함께 해당 없음 처리한다. 권한 기능이 있으면 사전 동의와 거부 시 나머지 기능의 정상 작동을 확인하고, 연결 기능은 가이드별 동작을 검증한다. |
| RCR-14 | 실제 광고 그룹 ID를 최신 소스·신규 커밋에 기록하지 않고 기존 이력은 보존한다. | 2026-10-05 사용자 선택으로 과거 이력 비노출 목표를 일반 커밋 최신 소스 정리·과거 이력 보존 정책으로 변경했다. 실제 groupId가 최신 원격 소스와 신규 커밋 스냅샷·추가 줄에 없어야 한다. 삭제 diff·부모 커밋·과거 이력에는 기존값이 남음을 명시한다. 외부 보호 입력과 기본/출시 빌드 분리를 검증한다. 최신 노출3브랜치 정리와 원격SHA·소스 검사 후 이 항목을 완료한다. 이력 재작성·강제push·그룹교체는 하지 않는다. 검색 결과는 실제값을 출력하지 않는다. |

## 공식 가이드 추적

| 가이드 영역 | 요구사항 |
| --- | --- |
| 사용자 식별키 발급 | RCR-01~RCR-03 |
| 서비스 이용 동작 및 기기 제스처 | RCR-04, RCR-07, RCR-08 |
| UX·인앱 광고 위치와 오클릭 | RCR-05, RCR-06, RCR-09 |
| 보안 및 안정성 | RCR-11 |
| 네비게이션·서비스 UX | RCR-12 |
| 조건부 기능·권한 | RCR-13 |
| 출시·검수 준비·저장소 보안 | RCR-10, RCR-14 |

## 완료 조건

- RCR-01~RCR-14의 적용 여부, 코드·자동·실기기 검증 결과 또는 해당 없음 근거를 남긴다.
- RCR-05의 화면 분류 결정과 근거를 남긴다. 적합하지 않은 화면에는 광고를 강행하지 않는다.
- 테스트 번들에는 테스트 ID만 포함되며 실제 ID는 테스트 산출물에서 검색되지 않는다.
- 토스 앱 실기기 확인 전에는 플랫폼 동작·실제 광고 노출을 통과로 표시하지 않는다.
- RCR-10은 외부 담당자 동의와 검수 상태를 구분한다. 문서 작성이나 테스트 번들 준비만으로 출시 완료 처리하지 않는다.
- 새 테스트 번들의 콘솔 업로드·테스트 푸시·QR 검증은 실행 단계에서 별도 승인을 받은 뒤 수행한다.
- 실제 groupId는 Git 원격 저장소에 push하지 않고, 푸시 전 민감값 검사를 통과해야 한다.
