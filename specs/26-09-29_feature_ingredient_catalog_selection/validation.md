# 검증 계획: 재료 카탈로그와 선택

이 문서는 구현 후 실행할 검증 절차다. 현재 기능 구현이나 검증이 완료되었다는 뜻은 아니다. 프로젝트에 별도 테스트 러너가 없으므로 수동 화면 확인과 기존 lint/build 명령을 사용한다.

## 기준 상태

- 마지막 구현 범위는 홈과 재료 선택 안내 화면이며, 실제 재료 데이터와 선택 로직은 아직 없다.
- 앞선 화면 검증에서 Chrome의 320×568 CSS px 뷰포트에 홈과 안내 화면이 잘리지 않고 표시됐다.
- 로컬 브라우저에는 `window.__appsInTossConstants`가 없어 TDS `SafeAreaInsets` 오류가 기록됐다. 실제 Toss WebView의 안전 영역 검증은 별도 앱인토스 확인 단계에서 수행한다.
- 이전 코드 기준 `npm run lint`와 `npm run build`는 종료 코드 0이었다. 기존 lint 경고와 TDS 번들 크기 경고는 기능 변경 후 비교한다.

## 요구사항별 검증

| 시나리오 | 동작 | 기대 결과 | 결과 |
| --- | --- | --- | --- |
| ING-VAL-01 최초 진입 | 홈에서 `재료 고르기`를 누른다. | 재료 선택 화면이 열리고 채소 카테고리가 기본 표시된다. | 미실행: 구현 후 확인 |
| ING-VAL-02 카테고리 | 다섯 탭을 차례로 누른다. | 각 탭에 정해진 재료만 표시되고 다른 카테고리의 선택은 유지된다. | 미실행: 구현 후 확인 |
| ING-VAL-03 다중 선택 | 같은 탭에서 재료 두 개를 고른다. | 두 버튼이 선택 상태이고 개수 2와 두 이름이 보인다. | 미실행: 구현 후 확인 |
| ING-VAL-04 선택 해제 | 선택한 재료를 다시 누른다. | 해당 재료만 해제되고 개수와 이름이 갱신된다. | 미실행: 구현 후 확인 |
| ING-VAL-05 카테고리 간 요약 | 다른 카테고리에서 재료를 추가한다. | 선택 개수와 이름에 모든 카테고리 선택이 포함된다. | 미실행: 구현 후 확인 |
| ING-VAL-06 홈 왕복 | 재료를 선택하고 홈으로 갔다 돌아온다. | 앞서 선택한 ID와 화면 표시가 유지된다. | 미실행: 구현 후 확인 |
| ING-VAL-07 빈 선택·초기화 | 처음에 0개인지 확인하고 재료 하나를 선택한 뒤 앱을 새로고침한다. | 처음에는 0개이고, 새로고침 뒤에도 0개로 초기화된다. | 미실행: 구현 후 확인 |
| ING-VAL-08 모바일·키보드 | 320 CSS px에서 보고 Tab/Enter/Space를 사용한다. | 가로 넘침이 없고 카테고리·재료 버튼을 키보드로 조작할 수 있다. | 미실행: 구현 후 확인 |
| ING-VAL-09 데이터 무결성 | 로컬 카탈로그의 ID와 category 값을 검토한다. | 28개 ID가 중복되지 않고 각 category가 타입과 일치한다. | 미실행: 구현 후 확인 |
| ING-VAL-10 코드 품질 | `npm run lint`, `npm run build`를 실행한다. | 두 명령이 오류 없이 끝난다. 기존 경고와 비교해 새 문제를 기록한다. | 미실행: 구현 후 확인 |

## 앱인토스 검증

재료 선택부터 메뉴 추천까지의 실기기 전체 흐름은 로드맵 7단계에서 확인한다. 이번 선택 화면 구현 후 브라우저 화면만 확인했다면 실제 Toss 앱 검증으로 표시하지 않는다.
