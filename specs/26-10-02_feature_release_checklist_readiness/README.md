# 비게임 출시 체크리스트 대응 및 출시 준비

2026-10-05 로드맵11단계 최신 원격 조사·노출 위치·대응 선택지는 [광고 ID 이력 대응](./ad-history-response.md)을 따른다. 최신5개 원격브랜치/태그0/연결36커밋 중 최신3브랜치·고유15커밋에 기존값이 남는다. 현재작업트리171파일0건과 구분하며,이력 대응 결정 전 전체 비노출 완료로 표시하지 않는다.

- 상태: 명세를 작업 브랜치에 이어받음. RCR-01~03·07은 [2026-10-04 명세](../26-10-04_feature_user_state_persistence/README.md)로 코드·자동 검증 완료, 실기기 및 나머지는 후속

## 목표

앱인토스 [비게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-nongame)에서 현재 코드만으로 충족을 확인하지 못한 항목을 정리하고, 코드 보완과 토스 앱 실기기·콘솔 출시 검증을 단계적으로 준비한다.

## 확인된 외부 상태 (2026-10-04 재조회, 이후 변동 가능)

- 앱은 비게임 미니앱이며 현재 콘솔 서비스 상태는 `PREPARE`다.
- 배너 광고 그룹은 `ENABLED`이고 실제 groupId가 발급됐지만, 최신 테스트 번들은 테스트됨으로 표시될 뿐 라이브 배포본은 없다.
- 출시 판정은 워크스페이스 제휴 약관 동의를 요구한다. 앱 정보 검토 상태는 승인됐지만 최초 등록 완료는 아니며 최초 번들 검수도 남아 있다.
- 10단계 검증 문서는 320×640 시각 점검과 QR 확인을 대기로 기록한다. 콘솔 최신 번들 `20261002-5`는 `isTested=true`로 표시되므로, 실제 화면·광고 확인 증거와 대조한 뒤 완료 여부를 판단한다.
- 현재 홈 전용 배너 요구와 가이드의 스크롤 가능 화면 및 인트로 화면 광고 제한이 충돌할 수 있다. 콘텐츠를 억지로 늘리거나 배너를 임의로 다른 화면으로 옮기지 않고 결정 게이트로 둔다.

## 범위

- 공식 비게임 사용자 식별키를 확인하고, 사용자별로 필요한 선택 상태를 앱 종료 후에도 복원한다.
- 지도 등 예외가 없으므로 화면 확대·축소 제스처 제한을 적용하고 확인한다.
- 배너의 스크롤 가능 여부, 인트로 분류, CTA와의 간격을 가이드와 광고 정책에 맞게 검토한다.
- 플랫폼 네비게이션, 스킴 진입, 반응 시간, 화면 넘침, 실제 광고 렌더링을 토스 앱에서 확인한다.
- 테스트 ID만 사용하는 테스트 번들을 검증하고, 워크스페이스 약관·최초 검수 등 출시 외부 선행 조건을 추적한다.
- 공식 가이드의 보안·네비게이션·UX 및 기능별 조건부 항목까지 적용 여부나 해당 없음 근거를 기록한다.

## 제외 범위

- 토스 로그인, 자체 로그인, 서버 연동, 결제, 토스페이, 공유 리워드, 위치·알림 권한을 새로 추가하지 않는다.
- 이번 로컬 구현 단계에서는 실제 groupId를 테스트 빌드에 넣지 않고 콘솔 업로드·출시·라이브 전환을 수행하지 않는다. 후속 새 테스트 번들의 업로드·테스트 푸시도 실행 시 별도 승인 게이트를 둔다.
- 배너를 표시하기 위해 의미 없는 콘텐츠나 빈 스크롤 공간을 추가하지 않는다.
- 현재 사용하지 않는 전면형·보상형 광고 샘플을 앱 흐름에 연결하지 않는다.

## 실제 광고 그룹 ID 보안

- 실제 groupId는 GitHub 등 원격 저장소에 push되는 코드·설정·문서·로그·커밋에 기록하지 않는다. 이 문서에도 실제 값을 적지 않는다.
- 원격 push 전 staged/unstaged/untracked 파일과 push 대상 커밋의 실제 groupId 노출을 값 자체를 출력하지 않는 방식으로 검사한다. 발견 시 push를 중단한다.
- 배포 구성에서 실제 ID가 필요하다면 저장소 밖의 승인된 보호 입력 경로를 사용한다. 테스트 빌드는 공식 테스트 ID를 유지한다.
