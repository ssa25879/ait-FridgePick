# 설계

## RSC-13 조리 단계의 사용 재료 반영

사용자가 승인한 [단계 재료 보완 설계](./step-required-ingredients.md)를 따른다. recipeStepIngredients.ts의 명시적192개 메뉴별 이름을 합성 recipes.ts의 지원/미지원 필요 목록에 합친다. 중복·선택 목록을 정리하고 난이도를 재계산한다. 자유 텍스트를 자동 파싱하지 않으며 원문 분량/단계/출처와 확인 안내를 유지한다. 이하의 필요 목록 불변 기록은 RSC-12 당시 설계다.

RSC-12 식약처 검색후보280개 후속은129개 검토안내와151개 문맥제외로 완료했다. 동의어·파생·부정문·도구/비유와 실제 누락/메뉴불일치를 구분해 메타데이터에만 반영했다. 기존 합성·준비판정·화면을 사용하고 원문/분량은 보존한다. [잔여대조 설계 근거](./mfds-remaining-review.md). 아래22개는 우선 검토 당시 범위다.

RSC-12 식약처 후속도 기존 안내 메타데이터를 사용한다. 888개 검색 후보280개 중 준비 완료22개를 우선 문맥 검토해13개 안내를 추가한다. 파생·동의어·선택·부정 문맥9개는 제외하며 자동 검색만으로 필수 재료를 추가하지 않는다. [식약처 검토 범위](./mfds-ingredient-review.md).

RSC-12는 Recipe.ingredientReviewNotes를 선택 메타데이터로 사용한다. 원본8개 ID의 확인 안내를 recipeIngredientReviews.ts에 분리하고 합성 카탈로그에서 적용한다. isRecipeReady는 기존두부족목록에더해검토안내도없어야true다. ResultPage는재료보유와원문확인필요를구분한다. 추천점수·후보포함·원문·로더를변경하지않는다. [대조 근거](./ingredient-review.md).

RSC-01: src/data/recipes.ts의 SOURCED_REPLACEMENT_RECIPES가 공식 ID20개를 참조한다. RECIPES는 대체 목록과 나머지 공공 카탈로그를 중복 없이 합친다. 데이터 원문은 생성 파일 publicRecipes.ts를 재사용하며 수기로 수정하지 않는다.

RSC-02: ResultPage의 기존 재료와 분량·출처·미지원 필수 재료 표시를 사용한다. 모든 재료에 정확한 g가 있다는 의미는 아니며 원문의 약간/적당량·개·컵 등도 그대로 둔다. 기본 매칭률60%와 난이도 규칙은 유지한다.

RSC-03: 카탈로그 무결성 검증은 실제 데이터로 수행한다. App 상태/탐색 테스트는 안정적인 합성 fixture로 분리하며 ResultPage.catalog.test.tsx는 실제 카탈로그와 getRecipeCandidates를 연결해 검증한다.

조리 단계의 원문 앞 번호(예:1.)는 화면의 ol 번호와 중복되지 않도록 렌더링에서만 제거한다. 생성 데이터와 조리 문장·수치·분량은 그대로 유지한다.

RSC-04: EPIS 기본·재료·과정을 RECIPE_ID로 결합해 정적 데이터로 생성하는 방식을 우선 검토한다. 현재 식약처 CSV 생성기에 다른 스키마를 바로 전달하지 않는다. 데이터 확보 뒤 전용 변환기를 설계한다. [필드와 확보 방법](./acquisition.md)을 따른다.

RSC-05: 기본60%/난이도 전체와 필수 재료 분모 규칙을 유지하며 추가 데이터와 명확한 재료 매핑으로 개선한다. 전체 카탈로그 수와 실제 후보 수를 분리한다. 구체적인 개선 폭은 전체 자료 확보 후 정하고, 최소한 대표 조합의 무결과율 감소를 확인한다.

재료 수집: scripts/downloadEpisIngredients.ps1은 SecureString 숨김 입력을 받아 Node 수집기에 표준입력으로 전달한다. 키를 앱 코드·환경변수·명령 인자·로그·내보내기에 저장하지 않는다. scripts/downloadEpisIngredients.mjs는 공식 JSON API를1000행 단위로 조회해 연속 행·전체 수·레시피별 재료 순번·분량 필드를 검사하고 새 폴더에 원문과 SHA256 manifest를 저장한다. 기본/과정 수집과 제품 편입은 별도다.

EPIS 편입: src/data/episCatalog.ts는 한국어 CSV 헤더와 재료JSON을 출처 ID로 결합한다. 과정 순서·팁을 보존하고 양념/부재료도 필수로 유지한다. 물은 기존 규칙에 따라 매칭 분모에서 제외하되 분량에는 표시한다. 원문 분량 없는 레시피, 누락/중복 조리 순서, 매핑60% 미만은 제외한다. 안심·호박·육수 같은 불명확한 이름은 임의 매핑하지 않는다. 난이도는 기존 단계/필수 재료 수 규칙을 재사용하며 원문의 난이도와 동일하다고 주장하지 않는다.

scripts/generateEpisCatalog.mjs는 UTF-8 또는 CP949 호환 euc-kr로 디코딩해 src/data/episRecipes.ts를 생성한다. 원본 이름·SHA256·확보일·기준일unknown·제외 사유/ID·기본정보 없는 ID·CSV 복구 수를 출력에 기록한다. 관측한 따옴표 오류1곳은 문장 그대로 복구하고 마지막 과정팁의 인용되지 않은 쉼표62행을 재결합한다. 다른 파싱 오류는 중단한다. 기존 식약처 생성 파일은 수정하지 않으며 recipes.ts에서 두 출처를 합친다. 이미지·외부 API 실시간 호출·키는 제품에 추가하지 않는다.

RSC-06: recipeCatalog.ts의 기존 동의어 테이블만 보완해 EPIS를 재생성한다. 신규 선택 재료·광범위한 부분 문자열 매핑·양념 자동 보유는 추가하지 않는다. 같은 식재료로 매핑돼도 원문 분량·가공 상태 설명·조리법은 계속 표시한다. 필수 재료가 모두 선택 가능한 수와 대표 조합별 후보 수를 함께 비교한다.

## RSC-08 주재료 중심 후보 계산

recommendRecipe.ts에서 원문 주재료 행을 우선 사용하고 등록 seasoning은 분모에서 제외한다. 원문 이름과 분량 사이 공백을 기준으로 해당 레코드에서 이미 확인된 재료 이름을 복원한다(2잎/1cup/반모 등). 임의 부분 문자열 동의어를 추가하지 않는다. 구분 없는 원문은 기존 필수ID 중 양념을 제외하고 미지원 필수 이름 전체를 분모에 유지한다. 원문이 없는 테스트·외부 레코드는 기존 필수 재료 방식으로 계산한다. 분모0은 후보에서 제외한다. 동일 레코드의 추출 결과는 WeakMap으로 재사용한다.

matchedRequiredIngredientIds와 두 missing 목록은 전체 필수 재료 기준으로 보존한다. matchBasis로 결과의 주재료 매칭률 표시를 구분하며 필터·결과에100%도 양념·부재료 준비가 필요할 수 있음을 안내한다. 난이도·랜덤 재추첨·저장 필터 수치·원문 생성 파일은 변경하지 않는다.

## RSC-07 합성 카탈로그의 매핑 정합성

원본 CSV가 없는 식약처 생성 파일은 그대로 보존한다. recipes.ts에서 공식 카탈로그를 합친 뒤 현재 mapRecipeIngredientName이 이미 인식하는 unmappedRequiredIngredients만requiredIngredients로 옮긴다. 필수ID는 중복 제거하고 동일ID의선택재료중복을제거한다. 인식하지못한문자열은그대로남긴다. 원문분량·조리과정·출처객체는변경하지않는다. 필수재료수변경이있는경우기존inferRecipeDifficulty로판정하고난이도규칙을완화하지않는다. 생성시점매핑통계와실제합성카탈로그통계는구분한다. 신규동의어나선택재료를추측해서추가하지않는다.

## RSC-09 개발 재현성

검증된 Node24.19.0을 .node-version에 고정하고 package.json/lock root의engines를>=24.15.0 <25로맞춘다. .npmrc의engine-strict로구버전설치를차단한다. CI는읽기전용권한으로잠금설치·앱테스트·수집기/생성기검사·lint·기본빌드와테스트광고ID검사를수행한다. 원본다운로드·출시ID·약관·배포는포함하지않는다. 원격실행통과와로컬명령통과는구분한다.

식약처생성기는기존CSV→정규화계약을유지하며입력바이트SHA256/파일명/확보일을추가한다. 확보일인자는기존기준일인자뒤에선택적으로받고미제공은unknown이다. 현재원본CSV부재로기존publicRecipes.ts는변경하지않는다. 공식페이지최종수정일2021-08-03도개별원본스냅샷기준일로사용하지않는다. EPIS는기존원본3개로임시재생성하고SHA256일치를확인한다. README는앱·설치·검증·원본상태·재생성·광고설정을중심으로바꾼다.

## RSC-10 로드맵13단계: 레시피 지연 로딩

App은RecipeMatch만type import한다. loadRecommendationModule.ts는추천모듈dynamic import Promise를공유하고실패하면캐시를지워후속호출을가능하게한다. 홈CTA의재료선택진입에서prefetch하고추천시완료를기다린다. 성공모듈은App의Ref에남겨재추첨에재사용한다. 빈선택은모듈대기없이빈결과안내를표시한다.

추천시preserveCurrentState를먼저호출하고동기pendingRef로중복을막는다. 요청버전을입력/필터변경·초기화·화면/플랫폼이동·언마운트에서무효화한다. 늦은완료/실패는현재버전과일치할때만결과·error·loading상태를갱신한다. IngredientPage는준비중disabled CTA와실패alert/재시도를표시한다. 원문데이터·추천계산·저장필터값·네비의최종화면규칙은유지한다.

## RSC-11 재료 준비 상태 분리

recipeReadiness.ts는 type import만 사용하며 두 부족 목록이 모두 비었을 때 준비 완료로 판정한다. App은 매칭 후보를 준비 완료/준비 필요로 나누고 준비 완료가 있으면 우선 선택한다. 활성 그룹 상태와 개수를 ResultPage에 전달하며 전환·재추첨은 해당 그룹만 사용한다. 화면은 준비 여부와 주재료 매칭률을 구분하고 보유 분량 미확인을 안내한다. 카탈로그와 로더는 수정하지 않으며 홈의 지연 로딩 경계는 유지한다.
