# 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| USP-01 | 공식 사용자 식별 | SDK 3.2.0의 `User.getAnonymousKey.isSupported()` 확인 후 호출. 유효한 HASH만 사용. 미지원·거부·잘못된 응답이면 세션만 사용 |
| USP-02 | 최소 데이터 저장 | 재료 ID 배열, 0.6~1.0 매칭률(0.05 간격), all/easy/normal/hard만 버전 1 JSON으로 저장. 현재 화면·추천 결과·사용자키를 JSON에 저장하지 않음 |
| USP-03 | 사용자 분리 | 사용자별 별도 키로 읽고 쓴다. 키 확인 전에는 읽기/쓰기 금지. 공용·임의 fallback 키 금지 |
| USP-04 | 상태 복원 | 동일 사용자 재진입 시 재료·필터 복원, 화면은 홈. 알 수 없는 재료 ID·중복 제거, 잘못된 필터는 60%·전체. 파싱 실패·다른 버전은 기본값 |
| USP-05 | 늦은 복원과 초기 덮어쓰기 방지 | 복원 전 기본값을 저장하지 않는다. 조회 중 사용자가 재료/필터를 변경하거나 추천/처음부터를 실행했으면 현재 세션을 우선하며 늦은 저장값은 적용하지 않음 |
| USP-06 | 실패·지연 처리 | 초기 조회 전체가 1,500ms를 넘으면 해당 마운트에서는 세션만 사용하고 늦은 응답은 무시. 읽기 오류 시 기존 데이터를 덮어쓰지 않음. 쓰기 오류에도 추천 가능, 다음 변경에서 재시도 |
| USP-07 | 쓰기 순서·초기화 | 동일 사용자 쓰기를 직렬화해 느린 과거 저장이 최신 선택/초기화를 덮지 않게 함. 처음부터는 선택 0개·60%·전체를 저장. 다른 사용자 저장은 변경하지 않음 |
| USP-08 | StrictMode·언마운트 | 정리된 초기 조회가 화면이나 저장을 변경하지 않음. 마운트당 조회 Promise를 재사용하고 네이티브 이벤트 구독을 정리 |
| USP-09 | 플랫폼 뒤로가기·홈 | 내부 화면에서 backEvent: 결과→재료→홈. homeEvent: 홈. 선택 유지. 홈에서는 구독을 해제해 플랫폼 기본 종료를 방해하지 않음. 실패 시 화면 내 홈/재료 버튼은 유지 |
| USP-10 | 실제 기기 확인 | 토스 앱의 실제 HASH·저장·종료/재진입·Android 백·토스 네비게이션을 확인하기 전에는 기기 완료로 표시하지 않음 |

확장 기능, 새 의존성, 자체 서버, 로그인, 권한 요청, 공용 게스트 저장소는 추가하지 않는다. SDK의 실제 사용자키·저장값·오류 객체를 로그에 출력하지 않는다.
