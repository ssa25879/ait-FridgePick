# 계획

체크 표시는 실제로 수행·검증한 항목에만 한다. 이 문서 준비 시점에는 모두 미수행이다.

## 순서와 이유

노출 정책이 10-22에 바뀌므로 **측정(1단계)과 무비용 콘솔 작업(2단계)을 먼저** 한다. 공유(3단계)는 코드 변경이 있어 새 번들이 필요하다. 재방문·프로모션은 기준선이 생긴 뒤 판단한다.

## 1단계: 측정 기반 (코드 소규모, 새 번들 필요)

- [x] TASK-01 `eventLog`는 deprecated, `Analytics.log` 사용으로 확인(타입 정의·공식 문서). 이벤트 이름은 소문자 스네이크로 통일. (ACQ-01)
- [x] TASK-02 `app_entry`, `ingredient_select_start`, `result_view`, `result_empty`, `reroll` 구현과 테스트 10개 추가(로컬 자동 검증만). (ACQ-01)
  - 완료 조건: 기존 테스트 전체 통과, 이벤트 기록 실패가 추천 흐름을 막지 않는다는 테스트 추가, 선택 재료가 이벤트에 들어가지 않는다.
- [ ] TASK-03 새 번들 업로드 후 콘솔 이벤트 로그에 단계별 값이 들어오는지 확인한다. 업로드·검수는 사용자 승인 후. (ACQ-01)
- [ ] TASK-04 콘솔 `핵심 지표`에서 전환 지표(대표 `result_view`)와 활성 지표를 등록한다. 이벤트가 한 번 수집된 뒤 선택 가능한지 확인하고, 변경은 다음 날 적용된다. (ACQ-02)

## 2단계: 콘솔 메타데이터 (코드 없음, 사용자 승인 필요)

- [x] TASK-05 상세 설명을 현재 정책과 대조해 수정안 작성. 콘솔 적용은 미수행. [초안](./metadata-draft.md) (ACQ-03)
- [ ] TASK-06 수정안 확정과 콘솔 적용. 초안은 작성했으나 사용자 승인 전이고 키워드 허용 개수는 미확인. (ACQ-03)
- [x] TASK-07 취소: 19세 이상은 플랫폼 조건이라는 사용자 정정으로 작업하지 않는다. (ACQ-04)
- [ ] TASK-08 메타 변경 전후 날짜를 기록해 검색 유입 변화를 비교할 수 있게 한다. (ACQ-09)

## 3단계: 공유 (코드, 새 번들 필요)

- [x] TASK-09 `Share.createLink`/`Share.sendMessage` 시그니처 확인(기존 `getTossShareLink`·`share`는 deprecated). OG 이미지는 https 절대 경로 호스팅이 확인되지 않아 이번에는 사용하지 않음. (ACQ-05, ACQ-06)
- [x] TASK-10 결과 화면에 "결과 공유하기" 버튼(TDS Button large)과 `share_tap` 이벤트 구현, 자동 테스트 통과. 320×640 시각 확인과 광고 비겹침은 미수행. (ACQ-05)
- [x] TASK-11 공유 문구에 "공식 파트너"·"입점사"·"제휴사"가 없음을 테스트로 확인. (ACQ-06)
- [ ] TASK-12 실기기에서 공유 창·링크 진입 확인. 브라우저 모의 결과를 기기 검증으로 표시하지 않는다. (ACQ-05)

## 4단계: 리뷰·재방문 (기준선 확보 후)

- [x] TASK-13 `Review.request` 구현: 바로 만들 수 있는 메뉴를 2번째로 볼 때 기기당 1회, 요청 기록을 먼저 저장. 기준 2회는 근거 없는 시작 가정. 자동 테스트 통과, 실기기 미확인. (ACQ-07)
- [ ] TASK-14 알림 제안 필요성을 지표(D1·D7)로 판단. **이번에는 구현하지 않음**: 판단할 지표가 아직 없고(기준선 약 5명), 추천 미니앱 UX 원칙이 불필요한 알림 동의를 빼라고 한다. (ACQ-08)

## 5단계: 외부 홍보·프로모션 (선결 조건 있음)

- [ ] TASK-15 사용자가 직접 올리는 홍보 문구 초안: "토스에서 냉털픽을 검색해보세요" 형식, 배지 규칙 준수. (ACQ-06)
- [ ] TASK-16 프로모션은 사업자 등록·약관·비즈월렛 충전이 선행되어야 하므로 이번 계획에서 보류. 재개 조건을 decisions.md에 기록. (ACQ-09)

## 승인 지점

콘솔 설정 변경, 번들 업로드, 검토 제출, 출시, 푸시 발송, 외부 게시는 각각 사용자 승인이 필요하다. 이전 승인은 이번 작업에 이어지지 않는다.
