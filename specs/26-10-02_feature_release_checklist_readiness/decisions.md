# 결정 기록: 비게임 출시 체크리스트 대응 및 출시 준비

## 확정 사항

### 1. 범위는 출시 가이드에서 확인된 미충족 항목에 한정

- 결정: 사용자 식별·필요 상태 복원, 확대 제스처, 광고 위치·오클릭, 플랫폼 이동, 기기 안정성 및 출시 선행조건을 다룬다.
- 근거: 현재 저장소·콘솔 대조에서 이 항목들이 미구현·미확인 또는 외부 차단으로 나타났다. 새 로그인·결제·권한 기능은 만들지 않는다.

### 2. 사용자 식별키는 서버 로그인 대신 앱 내부 상태 관리에 사용

- 결정: 공식 비게임 `User.getAnonymousKey()`를 사용하고 사용자별로 필요한 선택 상태만 기기 로컬에 저장하는 방향으로 설계한다.
- 근거: 공식 문서는 별도 인증 화면이나 서버 없이 비게임 앱 내부에서 사용자를 식별하고 재방문 상태를 관리할 수 있다고 안내한다.
- 제한: 어떤 데이터를 “필요한 데이터”로 보존할지는 구현 전에 명세 요구사항으로 확정하며, 식별키를 서버로 보내지 않는다.

### 3. 기존 홈 전용 광고 선호를 임의로 바꾸지 않는다

- 결정: 광고 위치 충돌은 구현 전 게이트로 둔다. 홈이 스크롤 가능한 기능 화면이고 일시적인 인트로가 아니라고 확인되면 홈 하단을 유지한다.
- 근거: 기존 요청은 홈 하단 전용 광고다. 비게임 가이드는 배너를 스크롤 가능한 화면에 한정하고 인트로 등 일시 화면을 제외한다. 광고 정책은 CTA와 가까운 배치가 오클릭을 유발하지 않도록 요구한다.
- 제한: 홈이 이 조건을 통과하지 못하면 의미 없는 콘텐츠나 빈 공간을 추가하지 않는다. 다른 화면으로 옮기기 전 사용자 선택을 받는다.

### 4. 테스트 ID와 실제 광고 ID를 분리한다

- 결정: 테스트 번들은 공식 테스트 ID만 쓰며 실제 그룹 ID를 테스트에 포함하지 않는다.
- 근거: 공식 광고 가이드의 개발 테스트 기준이다. 실제 광고 노출은 출시 승인·라이브 환경에서 확인한다.

### 5. 실제 광고 그룹 ID를 원격 저장소에 기록하지 않는다

- 결정: 실제 groupId는 GitHub 등 원격 저장소로 push되는 tracked/untracked 파일, 커밋, 문서, 로그에 적지 않는다. 푸시 전 값이 노출되지 않도록 민감값 검사를 한다.
- 적용: 배포에 필요한 경우에만 저장소 밖의 승인된 보호 입력 경로를 검토하며, 지원 여부 확인 없이 특정 CI/환경변수 방식을 전제하지 않는다. 테스트 빌드는 공식 테스트 ID를 사용한다.

## 외부 상태 (2026-10-02 확인)

- 광고 그룹: `ENABLED`, abuse level `NONE`, groupId 발급됨.
- 미니앱: `PREPARE`, 라이브 번들 없음.
- 테스트 상태 해석: 콘솔의 최신 번들 `isTested=true` 표시는 기존 검증 문서의 QR 미실행 기록과 별개다. 번들 메타데이터만으로 실제 화면 진입·배너 표시 검증을 통과 처리하지 않고, 실행 기록과 기기 증거를 대조한다.
- 메타데이터: 승인 상태이나 최초 등록 완료 아님.
- 출시 판정: `WORKSPACE_TERMS_AGREEMENT_REQUIRED`.
- 해석: 대표관리자의 워크스페이스 약관 동의와 최초 앱/번들 검수가 완료되기 전까지 실제 출시·광고 검증이 막혀 있다.

## 구현 전 결정 또는 확인이 필요한 사항

- **광고 화면 분류:** 현재 홈이 “스크롤 가능한 화면”이며 인트로/일시 화면이 아닌지 문서·실기기·검수 기준으로 확인한다. 불명확하면 광고를 다른 화면으로 옮기기 전에 사용자 확인을 받는다.
- **보존 상태 범위:** 재료 목록과 필터를 앱 종료 후 복원하는 것으로 시작한다. 제품 의도와 다르면 구현 전에 범위를 조정한다.
- **저장소 지원 실패:** 사용자 식별키를 받을 수 없는 경우 핵심 기능은 세션 내에서 사용 가능하게 하고, 이를 출시 체크리스트에서 통과로 간주할 수 있는지는 실기기 검수로 확인한다.
