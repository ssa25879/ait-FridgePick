# 설계: 추천 필터와 레시피 출처 각주

## 구조

- `App`이 매칭률(기본 `0.6`)과 난이도 필터(기본 `all`)를 상태로 소유한다. 결과에서 필터 화면을 다시 열면 설정을 유지하고 `처음부터` 동작은 둘 다 기본값으로 초기화한다.
- `IngredientPage`는 두 설정을 controlled props로 받고, 추천 시작 시 현재 설정으로 계산하도록 전달한다.
- 순수 함수 `inferRecipeDifficulty(stepCount, requiredIngredientCount)`가 `RecipeDifficulty`를 반환한다. CSV 정규화 시 공개 레시피의 `difficulty`를 이 함수로 정하고 수기 데이터도 같은 기준의 값을 가진다.
- `getRecipeCandidates`에 선택적 `RecipeCandidateFilters`를 추가한다. 필수 재료 매칭률 기준과 난이도를 모두 만족하는 레시피만 후보에 포함한다. 기본 필터는 기존 동작과 같은 60%·전체 난이도다.
- `ResultPage`에서 기존 `데이터 출처` 상세 구역을 제거하고, 조리 순서 아래 결과 콘텐츠의 마지막에 `footer.result-source-footer`로 표시한다.

## 난이도 계약

`requiredIngredientCount = requiredIngredients.length + (unmappedRequiredIngredients?.length ?? 0)`이며 optional 재료는 포함하지 않는다.

| 난이도 | 조건 |
| --- | --- |
| `easy` | 단계 수 ≤6 그리고 필수 재료 수 ≤6 |
| `normal` | 위 쉬움 조건에 해당하지 않으며 단계 수 ≤10 그리고 필수 재료 수 ≤10 |
| `hard` | 단계 수 >10 또는 필수 재료 수 >10 |

단계 수와 필수 재료 수는 모두 낮을 때만 해당 난이도를 부여한다. 공개 CSV의 공식 난이도 열은 없으므로 이 결과는 프로젝트의 일관된 추정값이다.

## 화면

- 재료 화면의 선택 요약과 `메뉴 뽑기` 동작 근처에 매칭률 범위 입력과 난이도 필터를 둔다.
- 범위 입력에는 `60% 이상`처럼 현재 값을 읽을 수 있는 레이블과 출력값을 제공한다. 최소·최대는 60·100, 간격은 5다.
- 난이도 선택은 `전체`, `쉬움`, `보통`, `어려움` 버튼으로 제공하고 선택 여부를 `aria-pressed`로 알린다. 각 버튼의 터치 높이는 44px 이상이다.
- 출처 각주는 제공기관·데이터셋·원본 ID를 유지하며 보조 텍스트 13px 이상으로 결과 조리 정보 뒤에 표시한다.

## 검증

- 단위 테스트로 판정 경계와 후보 필터의 논리곱, 기본값 호환을 검사한다.
- 앱 테스트로 매칭률 조절, 난이도 선택, 추천, 결과→재료 수정 시 설정 보존, 처음부터 초기화를 확인한다.
- 결과 페이지 테스트로 출처 정보, 표시 순서 및 각주 의미 영역을 확인한다.
- AIT DevTools 또는 기존 로컬 확인 방법으로 320×640 CSS px에서 입력, 터치 영역, 스크롤, 각주와 CTA를 살핀다.
