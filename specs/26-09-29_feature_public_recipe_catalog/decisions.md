# 결정 기록: 식품안전나라 레시피 CSV 카탈로그

## 확정 사항

### 1. 실시간 API 대신 CSV 기반 정적 카탈로그

- 결정: 앱이 실행될 때 API를 호출하지 않는다. 제공 CSV를 로컬에서 검토·정규화해 빌드에 포함한다.
- 근거: 대상은 `ait-fridgepick` 앱인토스 WebView 미니앱이며, 현재 앱은 서버 없이 정적 React/Vite 및 AIT 번들로 동작한다. 사용자는 해당 DB 인증키가 이미 있고 CSV 다운로드가 가능하다고 확인했다.

### 2. 인증키는 클라이언트에 배포하지 않음

- 결정: 인증키는 공식 데이터 취득 절차를 수행하는 사람만 사용한다. 저장소, 앱 코드, Vite 클라이언트 환경 변수, 작업 로그에는 넣지 않는다.
- 근거: 키가 앱 번들에 포함되면 모든 설치·실행 환경에 노출된다. 공식 상세 페이지의 직접 파일 주소는 키를 URL 경로에 넣고 HTTP로 표기한다.

### 3. 원본 CSV와 배포 가능한 데이터 분리

- 결정: 원본 CSV는 로컬 입력으로만 보관하고 Git에 커밋하지 않는다. 앱용 파생 데이터는 이용 조건이 확인된 뒤에만 추가한다.
- 근거: 사용자가 제공한 실제 CSV의 구조는 확인했지만, 현재 확인한 API 상세 페이지에는 앱 내 정적 재배포와 가공에 대한 명시적 라이선스 결론이 없다.

### 4. 기존 레시피와 재료 ID를 보존하고, 매핑은 명시적으로 확장

- 결정: 기존 20개 레시피와 28개 재료 ID를 보존한다. 실제 CSV 분석에 따라 명시적인 별칭 및 재료 항목 확장을 검토하고, 근거가 모호한 필수 재료는 기존 ID에 임의 매핑하지 않는다. 지원하지 않는 필수 재료를 결과에서 조용히 감추지 않는다.
- 근거: 초기 토큰 탐색에서 기존 재료만으로 매핑되는 후보가 제한적으로 보였으나, 이는 최종 파서·정규화 결과가 아니다. 사용자가 선택할 수 있는 재료 범위와 추천 결과의 누락 재료 정보를 함께 설계해야 한다.

## 미확정 사항

- CSV에서 확정 파서·별칭 규칙으로 매핑 가능한 레시피 수와 기존 대표 입력의 추천 후보 변화
- 이용약관 또는 별도 문의를 통한 앱 내 정적 제공·변환·출처 표시 허용 여부
- 매핑이 충분하지 않을 때 선택 카탈로그를 확장할지, 데이터 출처를 바꿀지
- 데이터 갱신 주기와 앱 데이터 크기 한도

## 기준 자료 및 관찰

- [식품안전나라 조리식품의 레시피 DB 상세 페이지](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=COOKRCP01)는 CSV 다운로드 경로, 원본 필드, 파일 요청 주소를 안내한다.
- 같은 상세 페이지는 파일 다운로드를 인증키당 서비스별 1일 10회로 제한하며, 파일 URL의 형식은 HTTP 주소로 표기한다.
- 실제 CSV는 사용자가 제공해 구조를 확인했다. 데이터 재사용·재배포 권리 조건은 확인하지 않았다. 위 관찰만으로 상업 앱에서 재배포할 권리가 있다고 간주하지 않는다.
