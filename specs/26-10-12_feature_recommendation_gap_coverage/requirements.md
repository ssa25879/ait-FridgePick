# 요구사항

| ID | 완료 조건 |
| --- | --- |
| RGC-01 | 현재 상태의 기준선을 재현 가능한 방식으로 고정한다: 미지원 필수 재료 레시피 수, 이름별 빈도, 전체 선택 시 후보·준비 완료 수, 일상 조합 10개의 후보·준비 완료 수. 실제 `getRecipeCandidates`·`isRecipeReady`로 계산하고 로드맵 기록(1,215개)과의 3개 차이 원인을 기록한다. |
| RGC-02 | 미지원 이름을 빈도 순으로 분류한다: (가) 기존 선택 재료와 같은 뜻의 표기, (나) 새 선택 재료로 추가할 후보, (다) 모호하거나 재료가 아닌 이름(보존). 각 분류에 원문 근거(레시피 ID·원문 줄)를 남기고 추정으로 연결하지 않는다. |
| RGC-03 | (가)는 기존 재료에 매핑하고 (나) 중 사용자가 승인한 것만 선택 재료 카탈로그에 추가한다. 추가 재료는 카테고리·표시 이름·ID 규칙을 따르고 칩 화면과 선택 요약에서 정상 표시된다. (다)는 계속 "미지원 추가 준비"로 표시한다. |
| RGC-04 | 기존 규칙을 유지한다: 원문 분량·조리 순서·출처 불변, 60% 기본 기준, 주재료 중심 매칭, 양념 자동 보유 금지, 준비 완료 우선과 검토 안내(ingredientReviewNotes) 제외. 생성 파일은 직접 수정하지 않고 재생성 또는 합성 단계에서 반영한다. |
| RGC-05 | 효과를 RGC-01과 같은 방법으로 전후 비교한다: 미지원 레시피 수, 전체 선택 준비 완료 수, 일상 조합 10개의 준비 완료 수. 준비 완료가 늘어도 원문 불일치·검토 안내가 있는 레시피는 준비 완료가 되지 않는다. 합성 조합 결과를 실제 사용자 효과로 일반화하지 않는다. |
| RGC-06 | 기존 테스트 전체와 신규 테스트(매핑·카탈로그 무결성·전후 기준선)가 통과하고 lint·기본 빌드·AIT 산출물 검사가 통과한다. 실제 광고 ID 부재 검사를 유지한다. |
| RGC-07 | 새 번들의 실기기 확인(칩 개수 증가에 따른 화면·스크롤, 추천 결과 표시)은 사용자 결과가 필요하며 별도 단계다. 완료 전에는 로드맵을 완료로 표시하지 않는다. |
