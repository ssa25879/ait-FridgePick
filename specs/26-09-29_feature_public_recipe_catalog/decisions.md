# 결정 기록: 식품안전나라 레시피 CSV 카탈로그

## 확정 사항

### 1. 실시간 API 대신 CSV 기반 정적 카탈로그

- 결정: 앱이 실행될 때 API를 호출하지 않는다. 제공 CSV를 로컬에서 검토·정규화해 빌드에 포함한다.
- 근거: 대상은 `ait-fridgepick` 앱인토스 WebView 미니앱이며, 현재 앱은 서버 없이 정적 React/Vite 및 AIT 번들로 동작한다. 사용자는 해당 DB 인증키가 이미 있고 CSV 다운로드가 가능하다고 확인했다.

### 2. 인증키는 클라이언트에 배포하지 않음

- 결정: 인증키는 공식 데이터 취득 절차를 수행하는 사람만 사용한다. 저장소, 앱 코드, Vite 클라이언트 환경 변수, 작업 로그에는 넣지 않는다.
- 근거: 키가 앱 번들에 포함되면 모든 설치·실행 환경에 노출된다. 공식 상세 페이지의 직접 파일 주소는 키를 URL 경로에 넣고 HTTP로 표기한다.

### 3. 원본 CSV와 배포 가능한 데이터 분리

- 결정: 원본 CSV는 로컬 입력으로만 보관하고 Git에 커밋하지 않는다. 공공데이터포털의 해당 데이터 등록 항목에 표시된 이용허락범위에 따라 출처와 원본 ID를 보존한 레시피 텍스트 카탈로그를 생성할 수 있다.
- 근거: 식약처가 제공기관으로 등록된 공공데이터포털 개별 항목이 이용허락범위를 “제한 없음”으로 표시한다. 원본 이미지는 제3자 권리 여부를 별도로 확인하지 않았으므로 복사하지 않는다.

### 4. 기존 레시피와 재료 ID를 보존하고, 재료 카탈로그를 명시적으로 확장

- 결정: 기존 20개 레시피와 재료 ID를 보존하며 카탈로그를 총 100개로 확장한다. 모호한 원재료 이름은 ID에 임의 매핑하지 않는다. 전체 필수 이름의 60% 이상이 명시적으로 매핑된 레시피만 포함하고, 나머지 미지원 필수 이름도 결과에서 감추지 않는다.
- 근거: 제공 데이터의 식재료 표현이 기존 28개보다 넓었다. 100개 재료로 선택 범위를 넓히고, 미지원 원재료 이름은 매칭률과 부족 재료 안내에 함께 반영한다.

## 구현 결정 (2026-10-01)

### 5. CSV 파서는 구조를 검증하고 의미상 빈 값은 보존

- 결정: 파서는 잘못된 인용부호, 행별 열 수 불일치, 필수 헤더 누락, 빈·중복 원본 ID를 거부한다. 반면 레시피명·재료 설명이 비어 있거나 조리 단계가 없는 행은 파싱 단계에서 버리지 않고 보존한다.
- 근거: 실제 CSV에 재료 설명이 빈 행 3개, 조리 단계가 없는 행 1개가 있다. 이를 파싱 오류로 취급하면 원본 데이터 품질을 집계할 수 없다. 후속 정규화에서 제외 여부와 사유를 결정한다.
- 구현: `src/data/recipeCsv.ts`; 테스트는 `src/data/recipeCsv.test.ts`.

### 6. 원본 CSV는 보호하고 앱 카탈로그에는 출처와 ID를 보존

- 결정: 원본 CSV 자체는 저장소에 넣지 않는다. 정규화한 텍스트 레시피는 제공기관·원본 ID·출처 표시를 포함해 앱 카탈로그에 추가할 수 있다. 원본 이미지 필드는 현재 구현 범위에서 제외한다.
- 근거: 공공데이터포털 개별 데이터 항목의 이용허락범위는 “제한 없음”이다. 포털 공통 정책은 제3자 권리가 포함된 데이터에 대한 권리 확보를 요구하므로, 이미지와 같은 별도 자산은 확인 전 복사하지 않는다.

### 7. 정규화된 재료 매핑과 미지원 재료 처리

- 결정: 괄호 안의 수량·조리 준비 메모를 제거해 명칭을 파싱하고, 확인된 별칭 사전만으로 100개 재료 ID에 연결한다. 숫자 단위 수량뿐 아니라 재료명 뒤에 단위 없이 기재된 수량도 제거하며, 숫자로 시작하는 재료명은 보존한다. 물은 공통 조리 기반 재료로 보고 선택·매칭 대상에서 제외한다. 고명·장식·토핑·곁들임만 선택 섹션으로 처리하고 양념·양념장·소스·드레싱·밑간·부재료는 필수로 처리한다.
- 근거: 실제 CSV에서는 `돼지등심`, `올리브오일`, `청고추`처럼 앱 표시 이름과 다른 표현이 확인되었다. 유사도 자동 매핑은 잘못된 결과를 만들 수 있으므로 별칭을 명시한다.
- 결정: 필수 재료의 고유 명칭 가운데 매핑 비율이 60% 미만이거나 매핑된 필수 재료가 하나도 없는 레시피는 제외한다. 기준 이상에서 남은 미지원 필수 재료는 `unmappedRequiredIngredients`로 저장해 추천 점수 분모와 결과 부족 재료 표시에서 유지한다.
- 근거: 불완전 매핑을 숨기지 않으면서 실제 데이터의 사용 가능한 범위를 확보하고, 원문 재료 텍스트로 사용자에게 전부 공개하기 위해서다.

### 8. 결과 화면의 출처와 원문 정보

- 결정: 공개 레시피 결과에 원문 재료·분량, 식품의약품안전처 출처, 데이터셋, 원본 ID를 표시한다. 원본 전체 CSV 행과 이미지 자산은 포함하지 않는다.
- 근거: 명시 매핑과 출처 추적을 사용자에게 확인 가능하게 하고, 원본 자산의 추가 권리 검토 범위를 만들지 않기 위해서다.

### 9. 추천 후보 비교 해석

- 결정: 기존 매칭 임계값 60%는 유지한다. 고정한 대표 입력 10개와 seed `20261001` 카테고리 균등 합성 표본 100개를 비교하고, 합성 표본의 한계를 기록한다.
- 근거: 로컬 데이터만으로 실제 이용자의 냉장고 분포를 알 수 없다. 최신 재료 분류로 후보 없음이 대표 입력에서는 3/10으로 그대로였고, 재계산한 합성 표본에서는 94%→89%로 내려간 결과를 함께 기록해 데이터 추가 효과를 과장하지 않는다.

## 기준 자료 및 관찰

- [식품안전나라 조리식품의 레시피 DB 상세 페이지](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=COOKRCP01)는 CSV 다운로드 경로, 원본 필드, 파일 요청 주소를 안내한다.
- [공공데이터포털의 식품의약품안전처 조리식품 레시피 DB](https://www.data.go.kr/data/15060073/openapi.do)는 제공기관을 식품의약품안전처로 표시하고 이용허락범위를 “제한 없음”으로 안내한다.
- [공공데이터포털 이용정책](https://www.data.go.kr/ugs/selectPortalPolicyView.do)은 제3자 권리가 포함된 공공데이터에 대해 권리자의 정당한 이용허락 확보가 필요하다고 안내한다. 본 작업에서는 원본 이미지 자산을 앱에 복사하지 않는다.
- [식품의약품안전처 저작권정책](https://www.mfds.go.kr/wpge/m_34/de010803l001.do)은 식약처가 업무상 작성·공표했거나 저작재산권 전부를 보유한 저작물은 별도 허락 없이 이용 가능하다고 안내하고, 공공누리 미표시 자료는 등록 부서와 사전 협의를 요청한다. 이 정책만으로 COOKRCP01 개별 DB의 권리 상태를 확정하지 않는다.
- 같은 상세 페이지는 파일 다운로드를 인증키당 서비스별 1일 10회로 제한하며, 파일 URL의 형식은 HTTP 주소로 표기한다.
- 실제 CSV는 사용자가 제공해 구조를 확인했다. 데이터 항목의 공개 이용 범위를 근거로 텍스트 레시피를 출처와 함께 이용하고, 원본 CSV는 커밋하지 않는다.
