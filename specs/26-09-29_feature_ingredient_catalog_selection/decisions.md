# 결정 사항: 재료 카탈로그와 선택

## 검토 당시 사실

- 현재 `src/App.tsx`는 `home`과 `ingredients` 화면 상태만 가진다.
- 재료 선택 안내 화면은 `src/pages/IngredientSelectPlaceholder.tsx`다.
- 프로젝트 기획서는 `Ingredient`에 `id`, `name`, `category`를 두고 다섯 카테고리를 제안한다.
- 현재 `package.json`은 React/React DOM `^18.3.1`, TDS Mobile 및 AIT용 TDS `^2.5.1`을 선언한다. `specs/tech.md`의 React 19 표기는 오래된 값이다.

## 결정 (2026-09-29)

### 1. 카테고리 키

프로젝트 기획서의 코드 키 `vegetable`, `meat`, `eggDairy`, `carb`, `seasoning`을 사용하고, 화면에는 로드맵의 한국어 표시명으로 보여준다. 기존 자료와 새 요구사항 사이의 중복 분류 체계를 만들지 않는다.

### 2. 재료 ID

ID는 소문자 ASCII snake_case로 작성하고, 전체 카탈로그에서 유일하며 표시 이름과 독립적으로 유지한다. 예: `green_onion`, `cooked_rice`, `soy_sauce`.

### 3. 첫 카탈로그

요구사항 문서의 28개 항목을 시작 데이터로 둔다. 이는 첫 구현용 고정 데이터이며, 레시피 데이터 작업에서 핵심 재료 누락이 발견되면 별도 근거를 기록하고 조정할 수 있다.

### 4. 선택 상태

선택 ID 배열은 `App`이 소유하고 화면 이동 중 유지한다. 앱 새로고침·재실행을 넘는 저장은 하지 않는다. 저장소, 백엔드, 전역 상태 라이브러리를 추가하지 않는다.

### 5. 결과 흐름

이번 단계는 재료 탐색과 선택까지만 완료한다. 현재 화면 상태 타입에 `result`를 추가하거나 임시 메뉴 결과를 만들지 않는다. 결과 관련 1단계 체크 항목은 추천 결과 화면이 구현되는 후속 단계에서 함께 마무리한다.

### 6. TDS 선택 컴포넌트

기존 TDS 설치 버전을 유지한다. 설치된 2.5.1 선언에서 `Button`과 선택 상태가 있는 `ChipItem` API를 확인했다. 다섯 카테고리 이름을 좁은 화면에서도 가로 스크롤 없이 보여주도록 TDS `Button` 그리드를 쓰고, 재료는 `ChipItem` 버튼으로 표시한다. 이 작업을 위한 의존성 추가나 버전 변경은 하지 않는다.

### 7. 카테고리 조작 방식

카테고리는 ARIA 탭 목록 대신 `role="group"` 안의 TDS 버튼으로 구현하고, 각 버튼에 `aria-pressed`를 제공한다. 이 방식은 다섯 개의 긴 라벨을 두세 열로 배치해 좁은 화면에서 줄 바꿈할 수 있고, 기본 Tab·Enter·Space 조작을 유지한다. 정확한 320 CSS px 화면에서 넘침이 없는지는 별도 확인으로 남긴다.

## 범위 밖 메모

`specs/tech.md`의 React 버전 표기 갱신은 유용한 별도 정리지만, 이번 재료 선택 기능 문서 범위에서는 수정하지 않는다. 실제 설치 정보는 `package.json`과 `package-lock.json`을 기준으로 한다.
