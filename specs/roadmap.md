# 냉털픽 로드맵

이 문서는 앱인토스 미니앱 기획서의 MVP 범위를 작고 확인 가능한 작업으로 나눈다. 체크 항목은 구현 순서이며, 기능을 완료했다고 표시하려면 각 항목의 완료 기준을 확인한다.

## 현재 상태

- React·TypeScript·Vite 기반 프로젝트와 앱인토스 빌드 설정이 있다.
- `src/App.tsx`는 홈·재료 선택·결과 화면을 전환한다. 추천 결과 계산, 레시피 상세, 빈 상태, 처음부터 초기화와 화면 왕복 흐름을 구현했다.
- 2단계 재료 카탈로그·선택 기능을 완료했다. 로컬 28개 재료, 다섯 카테고리, 선택 요약을 제공하며 AIT DevTools 사용자 지정 320×640 CSS px 화면을 확인했다. Vitest 자동 테스트 5개가 카탈로그와 주요 선택 흐름을 검증한다.
- 3단계 레시피 데이터를 완료했다. 로컬 레시피 20개와 타입을 추가하고 기존 28개 재료 카탈로그 ID, 필수 재료 수, 조리 단계, 난이도를 자동 검증한다.
- 1·4·5·6단계 기능 구현, 20개 자동 테스트, 320×640 모바일 확인과 세 관점 심층 코드 리뷰를 마쳤다. 앱인토스 실기기 확인은 남아 있다.
- 프로젝트 기획서는 [`NaengteolPick_React_Project_Plan.md`](./NaengteolPick_React_Project_Plan.md)에 둔다.

## 0단계: 프로젝트 기반 확인

- [x] React·TypeScript·Vite 프로젝트 뼈대와 의존성을 준비한다.
- [x] 앱인토스 설정 파일과 `dev`, `build`, `deploy` 스크립트를 준비한다.
- [x] `npm run dev`로 현재 화면이 브라우저에 뜨는지 확인한다.
- [x] `npm run lint`와 `npm run build`를 실행해 기준 상태를 기록한다.

## 1단계: 냉털픽 화면 뼈대

- [x] 샘플 시작 화면을 냉털픽 소개 화면으로 바꾼다.
- [x] 소개 화면에 서비스 설명과 재료 선택 시작 버튼을 둔다.
- [x] 화면 상태를 홈, 재료 선택, 결과로 나눈다.
- [x] 홈에서 재료 선택 안내 화면으로 이동한다.
- [x] 추천 결과에서 처음 화면으로 돌아가는 동작을 연결한다.
- [x] 모바일 폭에서 화면과 주요 버튼이 잘리지 않는 기본 레이아웃을 만든다.

완료 기준: 홈에서 재료 선택·결과 화면을 거쳐 홈으로 돌아올 수 있다. 결과→홈 이후 재료 선택도 보존된다.

## 2단계: 재료 카탈로그와 선택

- [x] `Ingredient` 타입과 재료 ID 규칙을 정한다.
- [x] 채소, 고기, 계란·유제품, 탄수화물, 양념 카테고리를 정의한다.
- [x] 화면에 표시할 초기 재료 목록을 로컬 데이터로 작성한다.
- [x] 카테고리별 재료 목록을 화면에 표시한다.
- [x] 재료 칩을 눌러 선택하고 다시 눌러 해제할 수 있게 한다.
- [x] 선택된 재료와 전체 선택 개수를 표시한다.
- [x] 화면 이동 후에도 현재 선택 상태를 유지한다.

완료 기준: 사용자가 카테고리별 재료를 여러 개 선택·해제하고 선택 목록을 확인할 수 있다. 확인 결과: 28개 재료, 다중 선택·해제, 홈 왕복 상태 유지, AIT DevTools 320×640 CSS px 화면을 검증했다.

## 3단계: 레시피 데이터

- [x] `Recipe` 타입에 필수 재료, 선택 재료, 조리 단계, 난이도를 정의한다.
- [x] 레시피를 로컬 TypeScript 또는 JSON 데이터로 관리한다.
- [x] 첫 레시피 묶음으로 메뉴 20~30개를 작성한다. (20개)
- [x] 각 메뉴에 필수 재료 3~6개 정도를 지정한다.
- [x] 레시피별 조리 단계를 3~5개의 짧은 문장으로 작성한다. (각 3단계)
- [x] 재료 ID 참조와 레시피 필수 데이터가 유효한지 확인한다. (`npm test`)

완료 기준: 레시피가 타입 오류 없이 로드되고, 각 레시피가 화면에서 사용할 재료 ID와 조리 단계를 가진다. 확인 결과: 20개 레시피, 7개 테스트 통과, lint 및 TypeScript/Vite/AIT 빌드 성공. lint의 기존 광고 훅 경고와 Vite 대형 청크 경고는 남아 있다.

## 4단계: 메뉴 후보 계산과 추천

- [x] 선택 재료와 레시피 필수 재료의 교집합을 계산한다.
- [x] 레시피별 보유 필수 재료 수와 전체 필수 재료 수를 계산한다.
- [x] 매칭률과 부족한 필수 재료 목록을 계산한다.
- [x] 후보 기준을 필수 재료 매칭률 60% 이상(경계 포함)으로 확정한다.
- [x] 기준을 만족하는 레시피만 추천 후보로 만든다.
- [x] 후보가 여러 개면 하나를 무작위로 고른다.
- [x] 다시 뽑을 때 후보가 2개 이상이면 직전 메뉴를 제외한다.
- [x] 후보가 없으면 빈 결과 상태를 반환한다.

완료 기준: 동일한 재료 입력에서 후보, 매칭률, 보유 재료, 부족 재료를 일관되게 계산한다. `optionalIngredients`는 후보 판정에서 제외한다.

## 5단계: 결과 화면과 다시 뽑기

- [x] 추천 메뉴 이름과 매칭률을 표시한다.
- [x] 선택 재료 중 해당 레시피에 쓰는 보유 재료를 표시한다.
- [x] 아직 필요한 필수 재료를 부족 재료로 구분해 표시한다.
- [x] 다시 뽑기 버튼이 현재 재료 선택을 유지한 채 추천을 갱신하게 한다.
- [x] 처음부터 버튼이 선택 상태를 초기화하고 재료 선택으로 돌아가게 한다.
- [x] 간단 조리 안내를 결과 화면에 표시한다. (기획서상 선택 기능)

완료 기준: 추천 메뉴와 재료 상태를 이해할 수 있고, 다시 뽑기와 초기화가 동작한다.

## 6단계: 빈 상태와 사용성 마무리

- [x] 재료를 하나도 선택하지 않은 경우의 안내를 정한다.
- [x] 추천 후보가 없는 경우 재료를 더 선택하도록 안내한다.
- [x] 후보가 하나뿐인 경우 다시 뽑기 동작을 자연스럽게 처리한다.
- [x] 로딩이나 오류처럼 보이는 불필요한 상태가 없는지 주요 흐름을 확인한다.
- [x] 모바일 화면에서 긴 메뉴명, 재료 목록, 버튼이 겹치거나 잘리지 않는지 확인한다.

완료 기준: 선택 0개, 후보 0개, 후보 1개, 후보 여러 개 상황에서 사용자가 다음 행동을 알 수 있다. 320×640 CSS px 미리보기에서 문서 가로 넘침이 없고 결과·빈 상태 콘텐츠는 세로 스크롤로 확인했다.

## 7단계: 검증 및 앱인토스 확인

- [x] 재료 선택·해제 후 선택 목록이 정확히 갱신되는지 확인한다.
- [x] `npm test`로 카탈로그와 재료 선택 사용자 흐름을 자동 검증한다.
- [x] 교집합, 매칭률, 부족 재료 계산을 대표 입력으로 확인한다.
- [x] 후보 기준 미만 레시피가 제외되는지 확인한다.
- [x] 후보가 둘 이상일 때 다시 뽑기로 다른 결과를 얻을 수 있는지 확인한다.
- [x] 후보가 없을 때 안내 상태가 표시되는지 확인한다.
- [x] `npm run lint`를 실행하고 오류를 해결한다.
- [x] `npm run build`를 실행하고 빌드 결과를 확인한다.
- [ ] 실제 앱인토스 미니앱에서 재료 선택부터 결과까지 한 사이클을 확인한다.

MVP 완료 기준: 서버 없이 핵심 흐름이 동작하고, 재료 선택부터 메뉴 추천까지 한 사이클이 짧고 안정적으로 끝난다.

## MVP 이후 검토

아래 기능은 MVP를 확인한 뒤 필요성이 드러난 경우 별도 범위로 진행한다.

- 즐겨찾기
- 제외 재료와 알레르기 필터
- 조리 시간·난이도 필터
- 외부 레시피 API
- AI 레시피 추천
