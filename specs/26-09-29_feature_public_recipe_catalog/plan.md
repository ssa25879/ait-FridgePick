# 구현 계획: 식품안전나라 레시피 CSV 카탈로그

작업 브랜치: `feature/public-recipe-catalog`

상태: CSV 분석과 초안 문서 작성 완료. 코드 구현은 시작 전이다.

## 진행 항목

- [x] 기존 레시피·재료 타입과 추천 계산 흐름을 확인한다.
- [x] 공식 데이터 설명과 앱인토스 정적 번들 구조를 확인한다.
- [x] 사용자가 제공한 CSV의 인코딩, 열, 레코드 수, ID 중복, 조리 단계 누락을 확인한다.
- [x] 요구사항·설계·결정·검증 초안과 로드맵 8단계를 작성한다.
- [x] 현재 상태와 다음 세션의 작업 순서를 `HANDOFF.md`에 기록한다.
- [ ] 앱 내 정적 제공·가공·재배포와 출처 표기 허용 여부를 공식 근거로 확인한다. 허용이 불분명하면 제공기관에 문의하고, 확인 전 파생 레시피를 앱 번들에 넣지 않는다.
- [ ] 원본 CSV를 Git에서 제외하는 ignore 규칙을 추가하고 staged diff에 원본·인증정보가 없는지 확인한다.
- [ ] CSV 파서와 입력 검증 테스트를 먼저 작성해 실패를 확인한 뒤 구현한다. BOM, 따옴표, 쉼표, 줄바꿈, 필수 열, 중복 ID, 빈 값 및 단계 번호를 다룬다.
- [ ] 재료 텍스트를 분석하고 명시적 별칭만 재료 ID에 연결한다. 미지원 필수 재료는 버리지 않고 추적하거나 해당 레시피를 제외 사유와 함께 기록한다.
- [ ] 필요한 선택 재료를 카탈로그에 추가할 범위를 정하고 모바일 선택 화면 사용성을 확인한다.
- [ ] 권리 조건이 허용할 때만 출처·원본 ID가 포함된 정적 후보 카탈로그를 생성한다. 기존 20개 레시피를 보존한다.
- [ ] 추천 계산에서 미지원 재료를 누락 없이 반영하고, 결과 화면에 출처와 필요한 재료를 명확히 표시한다.
- [ ] 레시피 수, 제외 건수·사유, 대표 선택 묶음별 후보 수와 후보 없음 비율을 기존 카탈로그와 비교한다.
- [ ] 요청된 검증을 실행하고 결과를 기록한다: 테스트, lint, `npm run build`, AIT 번들 크기, 320×640 모바일 화면 및 가능한 Toss 테스트 환경.
- [ ] 문서·외부 작업 로그를 갱신하고, 기능 파일만 명시적으로 stage해 커밋한다. `COOKRCP01.csv`, 기존 `Review.md`, 아이콘은 포함하지 않는다.

## 완료 조건

- 데이터 권리와 출처 표시 조건이 근거와 함께 확인되었다.
- 모든 포함 레시피와 재료의 ID·필수 필드가 유효하고, 제외 건수와 사유가 남아 있다.
- 원본 CSV와 인증정보가 저장소·앱 번들·로그에 포함되지 않는다.
- 기존 추천 기능이 보존되며 데이터 품질, 추천 후보 변화, AIT 빌드와 모바일 화면이 검증되었다.
