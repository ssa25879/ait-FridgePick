# 심층 코드 리뷰: 추천 결과 흐름과 메뉴 후보 계산

- 리뷰 시점: 2026-09-29, 1·4·5·6단계 구현 및 자동 검증 뒤
- 범위: 추천 계산, 재료 선택 및 결과 정보, UI 접근성·모바일 사용성
- 리뷰어: 기능, 재료 선택, UI 접근성 관점의 서브에이전트 3명

## 결과 요약

- Critical: 없음
- Important: 1건 확인 후 수정 완료
- Minor: 검증 보강 및 터치 영역 수정 완료
- 후속 리뷰: 세 리뷰어가 각 담당 수정 사항을 다시 확인했으며 차단 이슈가 없다고 판정했다.
- 실제 앱인토스 미니앱/실기기 검증은 별도 단계로 남아 있다.

## 관점별 결과와 조치

| 관점 | 리뷰 발견 | 조치 |
| --- | --- | --- |
| 기능 | optional 재료를 제외하는 테스트 데이터가 실제 optional 재료를 선언하지 않아 테스트가 동작을 직접 검증하지 못했다. | fixture에 optional 재료를 선언하고 optional 재료만 선택한 입력이 후보를 만들지 않는지 검증했다. |
| 재료 선택 | 레시피와 무관한 선택 재료가 결과의 보유 재료로 노출되지 않는다는 회귀 검증이 부족했다. | 결과 상세 테스트에서 레시피 선택 재료인 대파는 포함하고 무관한 치즈는 제외하는지 확인한다. 구현은 기존에도 레시피 재료 기준으로 필터링하고 있었다. |
| UI 접근성 | 화면을 조건부로 교체할 때 초점이 문서 본문에 남았다. 중요도 Important. | 각 화면의 main 영역에 `tabIndex={-1}`과 공유 ref를 연결하고 화면 상태가 바뀔 때 초점을 이동한다. 홈→재료→결과→홈 이동을 회귀 테스트와 모바일 브라우저로 확인했다. |
| UI 접근성 | 추천 결과 전체가 라이브 영역이라 조리 단계까지 한꺼번에 읽을 수 있었다. | 라이브 영역을 메뉴명과 매칭률만 포함하는 `role="status"`로 한정했다. 결과 상세 테스트에서 조리 단계가 포함되지 않는지 확인했다. |
| 모바일 사용성 | 카테고리 버튼 높이가 32px로 작았다. | 카테고리 버튼 최소 높이를 44px로 설정했다. 320×640 CSS px 브라우저에서 카테고리 버튼, 재료 칩, 결과 홈 버튼 높이를 모두 44px로 측정했다. 문서 너비 320px도 확인했다. |

## 재검증

- `npm test`: 5개 파일, 20개 테스트 통과.
- `npm run lint`: 종료 코드 0. 기존 광고 훅의 경고 1건.
- `npm run build`: TypeScript·Vite·AIT 빌드 성공. 500 kB를 초과하는 Vite 청크 경고가 남아 있다.
- 모바일 브라우저에서는 320×640 CSS px 결과 상세와 세로 스크롤을 확인했다. 실제 앱인토스 호스트 동작과 실기기 화면은 확인하지 않았다.
- 로컬 브라우저 로그에는 `window.__appsInTossConstants` 미주입에 따른 TDS `SafeAreaInsets` 오류가 있다. 이전 재료 선택 기능의 검증 때도 확인된 로컬 호스트 제한이며, AIT WebView에서 실제 값을 주입하는지는 미검증이다.
