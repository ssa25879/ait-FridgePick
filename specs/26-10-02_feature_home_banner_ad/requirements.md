# 요구사항: 홈 하단 배너 광고

## 목적

홈 화면에서만 표준 배너 광고를 표시해 수익화 지면을 마련하면서 재료 선택과 메뉴 추천 사용성을 유지한다.

## 포함 범위

- 홈 화면 하단에 배너 광고 하나를 표시한다.
- 공식 WebView 광고 SDK의 초기화, 지원 확인, 부착 및 해제 생명주기를 사용한다.
- 테스트 ID로 테스트 빌드를 만들고, 실제 그룹 ID는 테스트에 사용하지 않는다.
- groupId 발급은 테스트 구현의 선행 조건이 아니다. 실제 groupId를 출시 구성에 연결하는 작업은 발급 후 처리한다.
- 320×640 CSS px 레이아웃과 safe area, 기존 CTA 접근성을 확인한다.
- 앱인토스 빌드 산출물을 준비하고 광고 노출은 지원되는 토스 앱 환경에서 확인한다.

## 제외 범위

- 재료 선택·결과 화면의 광고
- 전면형·보상형 광고 흐름 변경
- 광고 클릭을 유도하는 문구, 보상 또는 별도 UI
- 실제 광고 ID를 사용하는 테스트 빌드
- 콘솔 업로드, 테스트 배포, 출시 또는 광고 지면 설정 변경
- 실제 groupId를 사용하는 출시 구성

## 요구사항

| ID | 요구사항 | 완료 조건 |
| --- | --- | --- |
| HAB-01 | 광고는 홈 화면에만 표시한다. | 홈 진입 시 슬롯이 부착되고 재료 선택·결과 화면에서는 슬롯과 광고가 보이지 않는다. |
| HAB-02 | 광고를 홈 하단에 배치한다. | 화면 너비 100%의 표준 배너 슬롯을 홈 콘텐츠 끝에 두고 버튼·안전 영역과 겹치지 않는다. 고정형 컨테이너는 문서 권장 높이 96px를 사용한다. |
| HAB-03 | SDK 생명주기를 지킨다. | StrictMode에서도 initialize를 앱 실행 중 한 번만 수행하고 initialize·attachBanner의 isSupported를 확인한다. 준비 완료 후 광고를 부착하고, 홈 화면 이탈 시 반환된 destroy를 호출한다. |
| HAB-04 | 광고 실패가 핵심 흐름을 막지 않는다. | 미지원, 초기화 실패, 광고 없음 또는 렌더링 실패 시에도 홈 소개와 재료 선택 CTA를 사용할 수 있다. |
| HAB-05 | 테스트 광고 정책을 지킨다. | 개발·테스트 빌드는 ait-ad-test-banner-id를 사용하고, 실제 광고 그룹 ID로 테스트하지 않는다. |
| HAB-06 | 지원 환경에서 광고를 확인한다. | 테스트 빌드를 콘솔 QR로 토스 앱에서 열어 실제 배너 렌더링을 확인한다. 샌드박스 미리보기는 광고 표시 검증으로 간주하지 않는다. |
| HAB-07 | 기존 앱 흐름을 유지한다. | 광고 부착·화면 이동·미지원 환경에서도 홈→재료 선택→결과 흐름과 버튼 접근성이 유지된다. |

## 완료 조건

- HAB-01~HAB-07 구현과 검증 결과를 기록한다.
- SDK 초기화 중복, 홈 화면 부착·해제, 미지원·광고 없음 상태를 자동 검증한다.
- 320×640 CSS px에서 배너, CTA, safe area가 서로 겹치지 않고 가로 넘침이 없다.
- 테스트 ID로 앱인토스 빌드를 만들고, 콘솔 QR을 통한 지원 환경 광고 확인 결과를 기록한다.
- 로드맵은 코드 구현과 검증이 완료된 뒤에만 완료 처리한다.
