# 냉털픽

> 초기 기획 원문이다. 현재 구현·변경된 타입·출시 범위는 [로드맵](./roadmap.md)과 날짜별 후속 명세를 우선한다.

**React 기반 앱인토스 미니앱 프로젝트 기획서**

> 냉장고 속 재료로 오늘의 메뉴를 추천해주는 미니앱

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | 냉털픽 (Naengteol Pick) |
| 플랫폼 | 앱인토스 WebView 미니앱 |
| 프론트엔드 | React + TypeScript + Vite |
| 개발 범위 | MVP 중심 / 서버·로그인·외부 레시피 API 제외 |
| 문서 버전 | v0.1 |
| 작성일 | 2026-09-29 |

> **핵심 원칙: “재료를 고르고 → 조건에 맞는 메뉴를 뽑고 → 바로 확인한다.”**

## 1. 프로젝트 개요

냉털픽은 사용자가 현재 냉장고에 있는 재료를 선택하면, 해당 재료로 만들기 쉬운 메뉴 후보를 찾고 그중 하나를 랜덤으로 추천하는 간단한 미니앱이다. 사용자는 “오늘 뭐 먹지?”라는 결정 비용을 줄이고, 남은 식재료를 활용할 수 있다.

| 구분 | 내용 |
| --- | --- |
| 문제 | 집에 재료가 있어도 어떤 메뉴를 만들지 결정하기 어렵다. |
| 해결 | 보유 재료를 빠르게 선택하고, 만들 수 있는 메뉴 후보 중 하나를 추천한다. |
| 핵심 가치 | 빠른 선택 / 남은 재료 활용 / 가벼운 재미 |
| 핵심 사용 시간 | 약 30초~1분 내 추천 완료 |

## 2. 목표와 비목표

### 2.1 MVP 목표

- 사용자가 보유 재료를 10초 안에 선택할 수 있다.
- 선택한 재료를 기준으로 추천 가능한 메뉴 후보를 계산한다.
- 후보 중 하나를 랜덤 추천하고, 사용 가능한 재료와 부족한 재료를 구분해 보여준다.
- 외부 서버 없이 프론트엔드만으로 전체 흐름을 완성한다.
### 2.2 MVP에서 제외

- 회원가입 및 로그인
- 서버/데이터베이스
- 외부 레시피 API
- 장보기·배달 연동
- AI 생성 레시피
- 사용자 간 공유/소셜 기능
- 복잡한 영양 정보 계산
## 3. 타깃 사용자 및 사용 시나리오

| 사용자 | 상황 | 필요 |
| --- | --- | --- |
| 1인 가구 | 냉장고에 자투리 재료가 남아 있음 | 적은 재료로 가능한 메뉴를 빨리 찾고 싶음 |
| 학생/취준생 | 간단한 한 끼를 해결해야 함 | 복잡한 레시피보다 쉬운 메뉴가 필요함 |
| 요리 초보 | 재료는 있지만 조합을 잘 모름 | 현재 재료 기준의 간단한 선택지가 필요함 |

### 3.1 대표 사용자 흐름

1. 앱 실행 후 “재료 고르기” 선택
2. 카테고리별 재료 체크
3. “메뉴 뽑기” 선택
4. 조건에 맞는 메뉴 후보 계산
5. 추천 메뉴 1개 표시
6. 마음에 들지 않으면 “다시 뽑기”
## 4. 핵심 기능 요구사항

| ID | 기능 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| F-01 | 재료 선택 | 카테고리별 재료를 다중 선택한다. | 필수 |
| F-02 | 선택 재료 확인 | 현재 선택 개수와 선택한 재료를 확인한다. | 필수 |
| F-03 | 메뉴 후보 매칭 | 레시피 데이터에서 선택 재료와 일치하는 후보를 계산한다. | 필수 |
| F-04 | 랜덤 추천 | 매칭된 후보 중 하나를 랜덤으로 선택한다. | 필수 |
| F-05 | 재료 구분 표시 | 보유 재료와 부족 재료를 분리해 보여준다. | 필수 |
| F-06 | 다시 뽑기 | 현재 선택 재료를 유지한 채 다른 후보를 추천한다. | 필수 |
| F-07 | 처음부터 | 선택 상태를 초기화하고 재료 선택 화면으로 돌아간다. | 필수 |
| F-08 | 간단 조리 안내 | 3~5단계 수준의 간단한 조리 순서를 표시한다. | 선택 |
| F-09 | 홈 하단 배너 광고 | 홈 화면 하단에만 표준 배너를 표시한다. 기본 테스트 빌드는 공식 테스트 광고 ID, release 빌드는 활성 발급된 실제 그룹 ID를 사용한다. | MVP 이후 |

## 5. 화면 구성

| 화면 | 주요 요소 | 동작 |
| --- | --- | --- |
| Home | 서비스 설명, 시작 버튼, (MVP 이후) 하단 배너 광고 | 재료 선택 화면으로 이동 |
| IngredientSelect | 카테고리 탭/칩, 선택 개수, 메뉴 뽑기 버튼 | 재료 선택/해제 후 추천 요청 |
| Result | 메뉴명, 매칭률, 보유/부족 재료, 조리 안내 | 다시 뽑기 또는 처음부터 |
| EmptyResult | 추천 가능한 메뉴 없음 안내 | 재료를 더 선택하도록 유도 |

### 5.1 와이어프레임 개요

```text
[냉털픽]
냉장고 속 재료로 오늘의 메뉴를 골라보세요.

[ 재료 고르기 ]

↓

[재료 선택]
채소 | 고기 | 계란/유제품 | 탄수화물 | 양념
[김치 ✓] [계란 ✓] [대파 ✓] [햄 ✓]

선택한 재료 4개
[ 메뉴 뽑기 ]

↓

오늘의 메뉴: 김치볶음밥
보유: 김치, 계란, 대파, 햄
부족: 밥
[ 다시 뽑기 ] [ 처음부터 ]
```

## 6. 추천 로직

MVP는 복잡한 AI 추천 대신, 로컬 JSON 데이터와 단순 점수 계산을 사용한다. 구현과 테스트가 쉽고 결과를 예측할 수 있다는 장점이 있다.

### 6.1 기본 매칭 점수

```text
matchCount = 선택 재료 ∩ 레시피 필수 재료 개수
requiredCount = 레시피 필수 재료 개수
matchRate = matchCount / requiredCount

예시
선택: 김치, 계란, 대파, 햄
김치볶음밥 필요: 밥, 김치, 계란, 대파
→ 3 / 4 = 75%
```

- 추천 후보 기준 예시: 필수 재료의 60% 이상 보유한 레시피만 후보에 포함한다.
- 후보가 여러 개면 랜덤으로 1개를 선택한다.
- “다시 뽑기” 시 직전 메뉴는 가능하면 제외한다.
- 후보가 0개면 선택 재료를 늘리도록 안내한다.
## 7. 데이터 모델

### 7.1 Ingredient

```ts
type Ingredient = {
  id: string;
  name: string;
  category: 'vegetable' | 'meat' | 'eggDairy' | 'carb' | 'seasoning';
};
```

### 7.2 Recipe

```ts
type Recipe = {
  id: string;
  name: string;
  requiredIngredients: string[];
  optionalIngredients?: string[];
  steps: string[];
  difficulty: 'easy' | 'normal' | 'hard';
};
```

난이도는 조리 단계 수와 전체 필수 재료 수를 기준으로 `easy | normal | hard`로 추정한다. 경계와 추천 필터는 [`specs/roadmap.md`](./roadmap.md) 9단계에 기록한다.

### 7.3 초기 레시피 데이터 규모

- 1차 목표: 20~30개 메뉴
- 각 메뉴는 필수 재료 3~6개 정도로 제한
- 조리 과정은 3~5단계의 짧은 문장으로 구성
- 처음에는 한식·간단식 중심으로 구성하여 데이터 제작 비용을 줄임

## 9. 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| UI | React + TypeScript | 컴포넌트 단위 구현과 타입 안정성 |
| 빌드 | Vite | 간단한 React 프로젝트 구성 및 빠른 개발 |
| 플랫폼 | 앱인토스 WebView | 웹 기술 기반 미니앱 구현 |
| 스타일 | CSS Modules 또는 일반 CSS | MVP에서 불필요한 의존성 최소화 |
| 데이터 | 로컬 TypeScript/JSON | 서버 없이 즉시 구현 가능 |
| 상태 | React 기본 상태 관리 | 작은 규모에 적합 |

## 10. 개발 단계와 검증 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 프로젝트 생성 및 기본 라우팅/화면 뼈대 | Home → 재료 선택 → 결과 화면 전환 가능 |
| 2 | 재료 데이터 및 선택 UI | 재료 다중 선택/해제가 정상 동작 |
| 3 | 레시피 데이터 작성 | 20개 이상 레시피를 타입 오류 없이 로드 |
| 4 | 추천 함수 구현 | 선택 재료 기준 후보/매칭률/부족 재료 계산 |
| 5 | 결과 화면 구현 | 추천 메뉴와 재료 정보 표시, 다시 뽑기 동작 |
| 6 | 예외 처리 | 선택 0개, 후보 0개, 후보 1개 상황 처리 |
| 7 | 앱인토스 환경 확인 | 실제 미니앱 환경에서 핵심 플로우 확인 |

### 10.1 최소 테스트 항목

- 재료를 선택/해제했을 때 선택 목록이 정확히 갱신되는가?
- 레시피의 필수 재료와 선택 재료의 교집합 계산이 정확한가?
- 매칭 기준 미만 레시피가 후보에서 제외되는가?
- 다시 뽑기 시 후보가 2개 이상이면 다른 결과가 나올 수 있는가?
- 후보가 없을 때 빈 화면 대신 안내 메시지가 표시되는가?
## 11. 완료 정의 (Definition of Done)

- 앱을 실행하면 오류 없이 Home 화면이 표시된다.
- 사용자가 재료를 1개 이상 선택할 수 있다.
- 추천 버튼을 누르면 조건에 맞는 메뉴 결과가 표시된다.
- 결과 화면에서 보유 재료와 부족 재료를 구분할 수 있다.
- 다시 뽑기와 처음부터 기능이 정상 작동한다.
- 모바일 화면에서 주요 버튼과 텍스트가 잘리지 않는다.
- 서버 없이 정적 빌드만으로 핵심 기능이 동작한다.
