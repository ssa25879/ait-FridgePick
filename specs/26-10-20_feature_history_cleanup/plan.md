# 계획 (세 세션)

체크 표시는 실제로 수행·검증한 항목에만 한다. 현재 모두 미수행이다. 각 세션은 시작 프롬프트([인수인계](./HANDOFF.md))로 시작하고 끝나기 전에 `D:\work\history-cleanup\STATE.md`에 결과를 기록한다.

## 공통 규칙

- 세션 1·2에서는 **삭제·덮어쓰기·강제 푸시를 하지 않는다.** 삭제는 세션 3의 마지막 게이트에서만 안내한다.
- `<AD_GROUP_ID>`의 실제 값을 채팅·문서·커밋·로그에 쓰지 않는다. 필요한 명령에는 파일 참조를 쓴다. (단, 이 세션 기록에는 이미 값이 남아 있다. 새 세션에서는 값을 다시 출력하지 않는다.)
- **동결:** 세션 1 시작부터 세션 3 끝까지 앱 기능 작업과 원격 푸시를 하지 않는다. 급한 수정은 동결을 해제할지 먼저 정한다.
- GitHub 설정(공개 범위, 이름 변경, 새 저장소, 삭제)은 **사용자가 직접** 한다. 어떤 화면에서 무엇을 누를지는 세션이 안내한다.
- 각 게이트에서 막히면 **중단하고 상태를 기록**한다. 중간 상태로 다음 세션을 시작하지 않는다.

## 세션 0 (지금, 사용자 1분 작업)

- [ ] S0-1 현재 저장소를 private로 바꾼다. (GitHub → Settings → General → Danger Zone → Change repository visibility → Make private.) 되돌릴 수 있다. 효과: 공개 노출 즉시 종료.
- [ ] S0-2 확인: 로그인하지 않은 브라우저에서 저장소 주소가 404가 되는지 본다. CI가 private에서도 동작하는지(Actions 사용 가능 여부)는 다음 푸시 때 확인된다.

## 세션 1: 백업·점검·연습 (원격은 건드리지 않음)

- [ ] S1-1 **백업(HC-01):** 위 설계의 백업 명령을 실행한다. 미러 복제본, 번들, 스태시 패치, 참조 목록(`git for-each-ref`)과 번들 SHA256을 `D:\work\history-cleanup\backup\`에 만든다. `git bundle verify` 통과를 확인한다.
- [ ] S1-2 **외부 보관:** 백업 폴더를 다른 디스크나 클라우드에 복사하고 복사본의 SHA256이 같은지 확인한다. (위치는 사용자가 정한다, 결정 8번.)
- [ ] S1-3 **점검:** 정확 문자열 검색으로 ID가 있는 커밋·파일 목록을 확정하고, 일반 비밀 패턴(키·토큰·비밀번호·개인 키·서명 URL)을 이력 전체에서 검색한다. 결과를 `STATE.md`에 요약한다(값은 쓰지 않음).
- [ ] S1-4 **환경:** 사용자 승인 후 `pip install git-filter-repo`. 승인하지 않으면 `filter-branch` 대안으로 연습한다.
- [ ] S1-5 **치환 규칙 파일:** `D:\work\local-config\history-cleanup\replace-text.txt`를 만든다(ID는 파일에만).
- [ ] S1-6 **연습(HC-02·03·04):** 백업의 복제본에서 치환을 실행하고 [설계](./design.md)의 검증을 모두 수행한다. 정리본 `master` 끝으로 `npm ci`·`tsc -b`·`npm test`·`npm run test:scripts`·기본 빌드를 통과시킨다. `commit-map`/`ref-map`을 보관한다.
- [ ] S1-7 **보고:** 영향 범위(바뀐 커밋 수, 참조 수), 검증 결과, 발견한 문제, 방식 A/B/C별 최종 권고를 정리해 사용자에게 보고한다.
- **게이트 G1:** 백업 검증 완료 + 연습 검증 전부 통과 + 사용자가 방식(A/B/C)과 결정 항목을 확정. 하나라도 실패하면 중단한다.
- **롤백:** 세션 1은 원격과 작업 저장소를 바꾸지 않으므로 롤백이 필요 없다(`D:\work\history-cleanup\` 삭제로 복구).

## 세션 2: 실행 — 방식 B (새 저장소)

(방식 C를 고르면 세션 2는 건너뛰고 세션 3의 문서·재발 방지 항목만 한다. 방식 A는 아래 "방식 A 대체 절차" 참고.)

- [ ] S2-1 **재확인:** 세션 1 이후 원격에 변경이 없는지(`git ls-remote`로 13개 참조 해시가 백업 때와 같은지), 백업이 그대로인지 확인한다. 다르면 중단하고 세션 1 일부를 다시 한다.
- [ ] S2-2 **사용자:** 옛 저장소 이름을 `ait-FridgePick-archive`(결정 3번에 따름)로 바꾼다. private 유지.
- [ ] S2-3 **사용자:** 새 빈 저장소를 만든다(private, README·.gitignore·license 추가 안 함, 기본 브랜치 `master`).
- [ ] S2-4 정리본에서 **`refs/heads/*`만** 새 저장소로 푸시한다(강제 푸시 불필요, 새 저장소가 비어 있음).
- [ ] S2-5 **검증(HC-07):** 새 저장소를 새 폴더에 복제해 참조별 커밋이 `ref-map`/정리본과 같고 ID가 0건이며 빌드·테스트가 통과함을 확인한다.
- [ ] S2-6 Actions 활성화와 CI 통과를 확인한다(워크플로가 private에서 도는지).
- [ ] S2-7 **로컬 전환:** 현재 `D:\work\ait-FridgePick`를 `D:\work\ait-FridgePick-old-<날짜>`로 **이름만 바꿔 보관**하고, 새 저장소를 `D:\work\ait-FridgePick`로 복제한다. 로컬 전용 브랜치·스태시는 결정 6번대로 처리한다.
- [ ] S2-8 **연동 점검:** 출시 빌드 설정(`D:\work\local-config`, 저장소 밖이라 영향 없음)을 새 복제본에서 `npm run build:release`로 확인한다(업로드는 하지 않는다), 기본 빌드 후 로컬 상태를 복원한다.
- **게이트 G2:** S2-5의 검증 전부 통과 + 사용자 확인. 통과 전에는 옛 저장소·옛 로컬 폴더에 아무것도 하지 않는다.
- **롤백:** 새 저장소를 삭제하고 옛 저장소 이름을 원래대로 되돌린 뒤 옛 로컬 폴더 이름을 복구한다. 옛 저장소와 옛 폴더는 변경하지 않았으므로 완전히 복구된다.

### 방식 A 대체 절차 (선택 시, 더 위험)

S2-1 재확인 → 브랜치별 기대 옛 SHA를 `STATE.md`에 기록 → `git push --force-with-lease=<브랜치>:<옛SHA> origin <정리본 브랜치>:<브랜치>`를 **하나씩**(기본 브랜치 `master`는 마지막) → 각 푸시 후 `ls-remote`로 해시 확인 → 모든 푸시 후 새 복제본으로 S2-5와 같은 검증. 브랜치 보호 규칙이 있으면 일시 해제가 필요하다. 롤백은 백업 번들에서 옛 해시로 다시 푸시하는 것인데 GitHub의 옛 커밋 캐시와는 무관하다.

## 세션 3: 정리·사후 조치

- [ ] S3-1 **문서 해시 갱신(HC-08):** `commit-map`으로 `Task.md`·`specs`의 옛 해시를 새 해시로 바꾸거나, 바꾸지 않고 "옛 → 새 대응표 위치"를 문서에 남긴다(결정 9번). 콘솔 번들 메모의 해시는 대응표로만 연결한다.
- [ ] S3-2 URL·설정 참조(`package.json`, README, CI, 문서의 저장소 주소)를 새 저장소에 맞춘다.
- [ ] S3-3 **새 저장소 공개 범위(결정 4번):** private 유지 또는 public 전환. public이면 전환 직전에 전체 이력을 다시 검색한다.
- [ ] S3-4 **광고 그룹(결정 5번):** 유지 또는 교체. 교체하면 새 지면 생성 → 약 2시간 반영 대기 → 설정 파일 갱신 → 출시 번들 재생성·검수는 별도 작업으로 분리한다.
- [ ] S3-5 **재발 방지(HC-10):** 커밋 전 비밀값 검사(정확 패턴 검색 스크립트 또는 훅)와 `AGENTS.md` 규칙("문서에는 비밀값 대신 자리표시자")을 추가하고 테스트한다.
- [ ] S3-6 **안정 확인:** 새 저장소로 일정 기간(제안 14일) 작업하며 문제 없음을 확인한다.
- [ ] S3-7 **삭제 게이트:** 아래를 **모두** 충족하고 사용자가 명시적으로 승인한 뒤에만 옛 저장소 삭제를 안내한다(삭제는 사용자가 직접). (a) 새 저장소 안정 운영 확인 (b) 외부 백업 SHA256 재확인 (c) 옛 로컬 폴더 보관 또는 이관 완료 (d) 삭제가 되돌릴 수 없다는 점을 사용자가 확인(GitHub의 삭제 복구 가능 여부는 공식 문서로 다시 확인해야 한다).
- **게이트 G3:** S3-1~S3-5 완료. 삭제는 선택 사항이며 G3와 별개로 진행한다.
- **롤백:** S3-7 이전까지는 옛 저장소·옛 폴더·백업이 모두 남아 있어 세션 2의 롤백이 그대로 가능하다.
