# 결정 기록: 홈 하단 배너 광고

## 1. WebView 배너 API

- 결정: @apps-in-toss/web-framework의 TossAds API를 사용한다.
- 근거: 앱은 React 기반 WebView 미니앱이며, 공식 WebView 가이드는 TossAds.initialize와 TossAds.attachBanner를 제공한다. 기존 useInAppAds는 전면형·보상형 광고를 다뤄 배너 API로 재사용하지 않는다.

## 2. 초기화 위치와 빈도

- 결정: App 최상위에서 지원 여부를 확인하고 앱 수명 동안 한 번만 초기화한다. 광고 슬롯은 홈 화면에서만 부착한다.
- 근거: 공식 문서는 앱 최상위에서 한 번 초기화하는 방식을 권장한다. 프로젝트는 React StrictMode를 사용하므로 effect 재실행에도 중복 호출하지 않도록 가드가 필요하다. 광고가 필요한 화면에서만 슬롯을 부착하면 화면별 노출 범위가 명확하다.

## 3. 표시 위치

- 결정: 홈 CTA 아래, 홈 레이아웃 마지막에 100% 너비·96px 높이 컨테이너를 둔다.
- 근거: 요청된 위치를 따르며 공식 고정형 배너 권장 크기를 사용한다. normal document flow 안에 두어 CTA를 덮지 않고 safe area를 지킨다.

## 4. 테스트와 실제 광고 ID

- 결정: 기본 개발·테스트 빌드는 공식 테스트 ID ait-ad-test-banner-id를 사용한다. `release` 모드 빌드만 콘솔에서 활성 상태를 확인한 실제 그룹 ID를 사용한다.
- 근거: 공식 가이드는 개발 중 테스트 ID 사용을 요구하며 실제 ID로 테스트하면 정책상 불이익이 있을 수 있다고 안내한다.
- 현재 상태: 2026-10-02 재조회에서 “배너 광고 1차” 지면이 ENABLED이고 groupId `[release ad ID: external local configuration]`가 발급된 것을 확인했다.
- 개발·테스트 정책: 기본 `build`는 공식 테스트 ID를 사용한다. 실제 ID로 테스트하지 않는다.
- 출시 구성: `build:release`가 활성 실제 groupId를 선택한다. 출시용 산출물을 콘솔 검수·출시하거나 실제 토스 앱에서 확인한 상태는 아니다.

## 5. 미지원·실패 처리

- 결정: 광고 SDK 미지원 또는 광고 로드 실패 시 광고 없이 홈을 계속 사용할 수 있게 한다.
- 근거: 광고 표시 여부가 핵심 기능인 메뉴 추천 흐름을 막아서는 안 된다.

## 6. 콘솔 조작 범위

- 결정: 이번 단계는 문서와 로컬 테스트 빌드 준비까지만 다룬다. 콘솔 업로드·테스트 푸시·출시는 별도 요청 없이는 진행하지 않는다.
- 근거: 테스트 빌드 준비와 외부 배포는 별도 동작이며, 현재 요청은 기능 설계·문서화 및 빌드 준비다.
