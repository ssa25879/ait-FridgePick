# 요구사항: 추천 결과 흐름과 메뉴 후보 계산

## 목적

재료 선택 결과를 기존 레시피 카탈로그와 비교해 만들 수 있는 메뉴를 계산하고, 한 가지 추천 결과를 화면에 표시한다. 사용자는 추천 결과에서 홈으로 돌아올 수 있다.

## 범위

### 포함

- 화면 상태를 `home | ingredients | result`로 관리한다.
- 재료 선택 화면에서 메뉴 추천을 시작해 결과 화면으로 이동한다.
- 결과 화면에서 홈으로 복귀한다. 이 이동은 선택 재료를 초기화하지 않는다.
- 필수 재료만으로 레시피별 보유·부족 ID, 보유 개수와 매칭률을 계산한다.
- 필수 재료 매칭률이 60% 이상인 레시피를 후보로 포함한다.
- 후보가 있으면 한 건을 무작위로 선택하고, 재추첨 시 후보가 둘 이상이면 직전 메뉴를 제외한다.
- 후보가 없거나 선택 재료가 없으면 `null` 추천 결과를 반환하고 빈 결과 안내를 표시한다.
- 결과 화면에서 보유 재료와 부족한 필수 재료 이름, 간단 조리 단계를 표시한다.
- `처음부터`를 누르면 선택 재료와 추천을 초기화하고 빈 재료 선택 화면으로 돌아간다.
- 후보 없음 안내에서 재료 선택 화면으로 돌아가면 기존 선택을 보존한다.
- 후보가 하나뿐이면 다시 뽑기 대신 단일 후보 안내를 표시한다.
- 작은 화면에서도 긴 이름, 재료 목록, 조리 단계와 버튼이 잘리지 않는다.
- 계산 규칙과 홈→선택→결과→홈 흐름을 Vitest로 검증한다.

### 제외

- 추천 후보 조정, 우선순위 점수, 재료 제외·알레르기 필터
- 앱 재시작 이후 저장 및 외부 API
- 앱인토스 실기기 배포 검수

## 추천 계산 계약

```ts
interface RecipeMatch {
  recipe: Recipe;
  matchedRequiredIngredientIds: string[];
  missingRequiredIngredientIds: string[];
  matchRate: number; // 0..1
}

getRecipeCandidates(
  selectedIngredientIds: string[],
  recipes?: Recipe[],
): RecipeMatch[];

pickRecipeCandidate(
  candidates: RecipeMatch[],
  previousRecipeId?: string,
  random?: () => number,
): RecipeMatch | null;
```

`matchRate`는 보유 필수 재료 수를 전체 필수 재료 수로 나눈 비율이다. `optionalIngredients`는 점수와 후보 판정에 포함하지 않는다. 60% 경계는 포함한다.

## 완료 조건

- 로드맵 1단계의 화면 상태와 결과→홈 이동이 동작한다.
- 선택 재료 기준 교집합, 개수, 비율과 부족 ID가 정확하다.
- 60% 미만 후보가 제외되고 60% 이상 후보가 포함된다.
- 후보가 여럿일 때 무작위 선택과 직전 결과 제외가 작동한다.
- 후보가 없는 경우에도 앱이 결과 화면에서 안내하고 홈으로 돌아갈 수 있다.
- 보유·부족 재료와 조리 단계를 결과에서 확인할 수 있고 처음부터 초기화가 작동한다.
- 0개·0 후보·1 후보·여러 후보 상태가 구분되어 다음 행동을 제공한다.
- `npm test`, `npm run lint`, `npm run build`가 종료 코드 0이다.
- 320×640 CSS px에서 새 추천 흐름 UI가 잘리지 않는다.
