# 사용자 상태 저장·복원과 플랫폼 이동

## 현재 정책: 2026-10-06 사용자 변경 요청

앱을 새로 실행하면 이전 선택을 복원하지 않고 재료0개·60%·전체로 시작한다. 선택 재료와 필터는 현재 실행의 React 상태로만 유지하고 사용자키 조회·저장소 읽기/쓰기를 수행하지 않는다. 같은 실행의 화면 왕복과 초기화·플랫폼 이동은 유지한다. 이전 저장값은 삭제하지 않고 무시한다.

아래의 자동저장·재진입 복원 명세와 과거 검증은 당시 정책에 대한 이력이다. 현재 요청은 기존 USP-02/04~08의 영속 저장·복원 동작보다 우선하며, 실제 변경·검증 범위는 [최신 검증](./validation.md)을 따른다. 토스 실기기 재실행 검증과 새 번들 업로드는 남는다.

- 작성일: 2026-10-04
- 브랜치: `feature/user-state-persistence`
- 문서 보완 브랜치: feature/release-validation-specs
- 구현 커밋: 3a9972c
- 상태: 문서·코드·자동 테스트·브라우저 mock 검증 완료, 실기기 QA 대기
- 요청: specs 정합성 개선 후 감사 보고의 보완내용 1번 진행
- 상위 요구사항: RCR-01~03, RCR-07의 뒤로가기·홈 이벤트 연결

서버·로그인 없이 사용자별로 선택 재료·매칭률·난이도를 보존한다. 앱을 다시 열면 홈부터 시작하고 저장한 선택을 재사용한다. SDK 실패가 추천을 막거나 다른 사용자의 데이터를 대신 읽는 일이 없어야 한다.

이 작업에는 광고 위치 변경, 화면 확대 제한, 실제 광고 ID 이전, 콘솔 업로드·출시를 포함하지 않는다. 네이티브 동작은 자동 테스트와 실제 토스 앱 QA를 구분한다.
