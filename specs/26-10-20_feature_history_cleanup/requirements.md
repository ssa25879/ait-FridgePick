# 요구사항

| ID | 요구사항 | 완료 조건 |
| --- | --- | --- |
| HC-01 | 모든 작업 전에 되돌릴 수 있는 완전 백업을 만든다 | 로컬 전용 브랜치·스태시·원격 추적 참조를 포함한 미러 복제본과 번들 파일이 있고, 번들 검증(`git bundle verify`)과 SHA256이 기록되며 두 곳 이상에 보관된다 |
| HC-02 | 정리 결과에 `<AD_GROUP_ID>` 원문이 어떤 형태로도 남지 않는다 | 모든 참조의 모든 커밋에서 정확 문자열 검색 0건, 객체 전체 검색(`git grep` 각 커밋) 0건 |
| HC-03 | ID 외의 내용은 바뀌지 않는다 | 옛 커밋과 새 커밋 쌍마다 diff가 해당 6개 파일의 치환 줄에만 있고 그 줄은 `<AD_GROUP_ID>`로만 바뀌었다 |
| HC-04 | 정리한 이력이 정상 동작한다 | 새 `master` 끝에서 `npm ci`, `tsc -b`, `npm test`, `npm run test:scripts`, 기본 빌드가 통과한다 |
| HC-05 | 되돌릴 수 있는 순서로만 진행한다 | 세션 1·2에서는 삭제·덮어쓰기가 없고, 각 단계에 롤백 방법이 있다 |
| HC-06 | 기존 저장소에는 강제 푸시를 하지 않는다(방식 B) | 방식 B 선택 시 기존 저장소의 어떤 참조도 변경하지 않는다 |
| HC-07 | 새 저장소를 확인한 뒤에만 전환한다 | 새 저장소를 새로 복제한 결과가 정리본과 참조별로 같고 ID가 0건이다 |
| HC-08 | 문서의 커밋 해시 참조를 새 해시와 연결한다 | 대응표(옛 → 새)로 `Task.md`와 `specs`의 해시를 갱신하거나 대응표 위치를 문서에 남긴다 |
| HC-09 | 삭제는 마지막에 명시 승인으로만 한다 | 새 저장소 안정 운영 확인, 외부 백업 확인, 사용자의 명시 승인이 모두 있을 때만 옛 저장소 삭제를 안내한다 |
| HC-10 | 재발을 막는다 | 커밋 전 비밀값 검사가 추가되고, 문서에는 비밀값 대신 자리표시자를 쓰는 규칙이 `AGENTS.md`에 있다 |
