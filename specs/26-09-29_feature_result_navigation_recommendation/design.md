# 디자인: 추천 결과 흐름과 메뉴 후보 계산

## 설계 기준

기존 `App`의 React 상태와 로컬 레시피를 그대로 사용한다. 계산은 화면에서 분리한 순수 함수로 구현하고, 새 상태 관리 라이브러리나 라우터는 추가하지 않는다.

## 화면 상태와 이동

```text
home → ingredients → result
  ↑                 │
  └──── 홈으로 ─────┘
```

- `App`이 `home | ingredients | result` 상태와 선택 재료 ID를 소유한다.
- 재료 화면의 `메뉴 뽑기` 동작은 후보를 계산하고 한 건을 선택해 결과 화면을 연다.
- 결과에서 `홈으로` 이동하면 화면만 바꾸고 선택 재료를 보존한다.
- 추천 결과가 없으면 같은 결과 화면에 빈 결과 문구를 표시한다.
- 결과 화면은 메뉴명·매칭률, 보유 재료, 부족 필수 재료, 조리 단계와 다시 뽑기·처음부터·홈 이동을 제공한다.

## 계산 모듈

`src/utils/recommendRecipe.ts`에서 `RECIPES`와 재료 선택 ID를 받아 후보와 추천을 계산한다.

1. 선택 ID를 `Set`으로 변환한다.
2. 각 레시피의 필수 ID를 보유·부족 목록으로 나눈다.
3. `matchedRequiredIngredientIds.length / recipe.requiredIngredients.length`를 계산한다.
4. 비율이 `0.6` 이상인 항목만 후보에 유지한다.
5. 후보가 없으면 `null`, 후보가 있으면 주입 가능한 난수 함수로 한 건을 뽑는다.
6. 다시 뽑을 때 후보가 둘 이상이면 직전 레시피를 선택 풀에서 빼고 무작위 선택한다.

선택 재료가 비었거나 레시피 필수 재료가 비어 있으면 유효 매칭 결과를 만들지 않는다. `optionalIngredients`는 추천 계산에서 제외한다.

## 화면 구성

- 재료 화면 선택 요약 아래에 `메뉴 뽑기` 버튼을 둔다.
- 결과 화면에는 제목, 추천 메뉴명, 매칭률, 선택한 보유 재료, 부족한 필수 재료와 조리 순서를 표시한다.
- 대체 후보가 있으면 `다시 뽑기`를 표시한다. 대체 후보가 없으면 같은 레시피가 반복된다는 혼란을 피하도록 버튼을 숨긴다.
- 추천 후보가 하나뿐이면 단일 후보 안내를 표시하고 `다시 뽑기`는 표시하지 않는다.
- 선택 재료가 0개이면 먼저 재료를 고르도록 안내한다. 선택 재료가 있지만 후보가 없으면 재료 추가·변경 안내를 표시한다.
- `재료 선택하기` 또는 `재료 추가·변경하기`는 선택 상태를 보존한 채 선택 화면으로 이동한다. `처음부터`는 선택을 비우고 선택 화면으로 이동한다.
- 모든 결과 상태에서 홈 이동을 제공한다.
- 결과 화면의 메뉴명은 짧은 뷰포트에서 줄바꿈되며 가로 넘침을 만들지 않는다.
