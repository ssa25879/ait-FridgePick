# 결정 기록: 비게임 출시 체크리스트 대응 및 출시 준비

## 확정 사항

### 1. 범위는 출시 가이드에서 확인된 미충족 항목에 한정

- 결정: 사용자 식별·필요 상태 복원, 확대 제스처, 광고 위치·오클릭, 플랫폼 이동, 기기 안정성 및 출시 선행조건을 다룬다.
- 근거: 현재 저장소·콘솔 대조에서 이 항목들이 미구현·미확인 또는 외부 차단으로 나타났다. 새 로그인·결제·권한 기능은 만들지 않는다.

### 2. 사용자 식별키는 서버 로그인 대신 앱 내부 상태 관리에 사용

- 결정: 공식 비게임 `User.getAnonymousKey()`를 사용하고 사용자별로 필요한 선택 상태만 기기 로컬에 저장하는 방향으로 설계한다.
- 근거: 공식 문서는 별도 인증 화면이나 서버 없이 비게임 앱 내부에서 사용자를 식별하고 재방문 상태를 관리할 수 있다고 안내한다.
- 제한: 어떤 데이터를 “필요한 데이터”로 보존할지는 USP-02 범위로 확정했으며, 식별키를 서버로 보내지 않는다.

### 3. 사용자 결정으로 재료 화면 배치 선택

- 확정: 2026-10-04 사용자가 재료 선택 화면 하단으로 이동하고 스크롤 조건을 적용하도록 선택했다.
- 근거: 홈320×640 비스크롤을 확인했고 실제 서비스 콘텐츠가 넘치는 재료 화면에 광고를 한정한다.
- 제약: 광고 높이로 스크롤을 만들지 않고 CTA32px 간격을 둔다. 이 값은 공식 최소 거리로 단정하지 않으며 기기·검수 적합성을 확인한다.

### 4. 테스트 ID와 실제 광고 ID를 분리한다

- 결정: 테스트 번들은 공식 테스트 ID만 쓰며 실제 그룹 ID를 테스트에 포함하지 않는다.
- 근거: 공식 광고 가이드의 개발 테스트 기준이다. 실제 광고 노출은 출시 승인·라이브 환경에서 확인한다.

### 5. 실제 광고 그룹 ID를 원격 저장소에 기록하지 않는다

- 결정: 실제 groupId는 GitHub 등 원격 저장소로 push되는 tracked/untracked 파일, 커밋, 문서, 로그에 적지 않는다. 푸시 전 값이 노출되지 않도록 민감값 검사를 한다.
- 적용: 배포에 필요한 경우에만 저장소 밖의 승인된 보호 입력 경로를 검토하며, 지원 여부 확인 없이 특정 CI/환경변수 방식을 전제하지 않는다. 테스트 빌드는 공식 테스트 ID를 사용한다.

## 외부 상태 (2026-10-02 확인)

- 광고 그룹: `ENABLED`, abuse level `NONE`, groupId 발급됨.
- 미니앱: `PREPARE`, 라이브 번들 없음.
- 테스트 상태 해석: 콘솔의 최신 번들 `isTested=true` 표시는 기존 검증 문서의 QR 미실행 기록과 별개다. 번들 메타데이터만으로 실제 화면 진입·배너 표시 검증을 통과 처리하지 않고, 실행 기록과 기기 증거를 대조한다.
- 메타데이터: 승인 상태이나 최초 등록 완료 아님.
- 출시 판정: `WORKSPACE_TERMS_AGREEMENT_REQUIRED`.
- 해석: 대표관리자의 워크스페이스 약관 동의와 최초 앱/번들 검수가 완료되기 전까지 실제 출시·광고 검증이 막혀 있다.

## 구현 전 결정 또는 확인이 필요한 사항

- **광고 기기/검수 적합성:** 현재 재료 화면의 조건부 배치 결정은 확정했으나 Ad·safe area·오클릭·검수는 미확인이다.
- **보존 상태 범위:** 재료 목록과 필터를 앱 종료 후 복원하는 것으로 시작한다. 제품 의도와 다르면 구현 전에 범위를 조정한다.
- **저장소 지원 실패:** 사용자 식별키를 받을 수 없는 경우 핵심 기능은 세션 내에서 사용 가능하게 하고, 이를 출시 체크리스트에서 통과로 간주할 수 있는지는 실기기 검수로 확인한다.

## 2026-10-04 실행 결정

- 보존 범위는 재료 선택 ID·매칭률·난이도로 확정했다. 사용 이력·추천 결과·계정 기능은 추가하지 않는다.
- 동기 브라우저 저장 대신 SDK Storage의 비동기 API를 사용한다. 상세 실패·경합 계약은 상태 저장 명세를 따른다.
- 기존 홈 광고의 비스크롤 상태는 320×640 브라우저에서 재현됐다. 기기·정책 최종 판단과 광고 위치 변경은 이번 작업과 분리한다.
- 실제 광고 ID는 기존 코드/원격 이력에 존재한다. groupId를 인증 비밀키로 단정하지 않는다. 원격 비노출 목표를 이미 달성한 것으로 기록하지 않고 후속 보호 입력/이력 대응으로 남긴다.

## 2026-10-04 광고 배치 결정 갱신

사용자의 직접 선택으로 홈 전용 선호/위치 변경 대기 결정을 대체한다. 재료 선택 화면의 메뉴 뽑기 아래로 이동하고 광고를 제외한 콘텐츠가 실제로 viewport를 넘을 때만 노출한다. 조건이 사라지면 해제하며 홈/결과에는 표시하지 않는다. [상세 명세](../26-10-04_feature_ingredient_banner/README.md)를 따른다. 실기기·검수 적합성은 미확인이다.

## 남은 실행 결정

대상 기기/토스 버전·새 테스트 번들 업로드 일정·실제 광고 승인 후 확인 시점은 미정이다. 실제 ID 보호 입력 방법과 기존 원격 이력 대응은 미확정이다. 기존 push 요청은 사용자 지시로 수행했지만 원격 비노출 목표를 달성했다고 해석하지 않는다. 재조회 없는 콘솔 상태는 이전 확인 기록으로만 사용한다.

## 2026-10-05 RCR-14 보호 입력 구현

사용자의4번 작업 진행 요청에 따라 기존 광고 모드 분기 구조를 유지하고 실제 ID의 보호 입력을 구현했다. 실제 ID는 소스/테스트에서 제거하고 저장소 밖 ../local-config/ait-fridgepick/.env.release.local에 보존한다. 기본 빌드는 이 파일을 읽지 않으며 release만 FRIDGEPICK_BANNER_AD_GROUP_ID를 loadEnv로 읽는다. 로컬 설정은 저장소 밖 기본 경로만 사용하며, CI에서는 빌드 프로세스의 보호 환경변수로 제공할 수 있다. 빈 값·공식 테스트ID·잘못된 형식은 출시 빌드를 중단하고 입력 값을 오류에 출력하지 않는다. 실제 ID는 SDK 동작을 위해 출시 클라이언트 번들에 포함되며 이 분리는 Git 소스 비노출을 위한 것이다.

기존 원격 코드/이력은 정리되지 않았다. 확인한 로컬 origin 추적 참조5개에 기존 값이 남는다(현재 원격 전체의 실시간 조사 아님). 현재 작업 트리와 신규 파일에는 값이 없으며 삭제 diff의 이전 줄과 부모 커밋에는 기존 값이 남는다. 선택지는 일반 커밋으로 최신 브랜치 소스를 제거하고 이력을 보존하거나,별도 승인 후 관련 원격 참조/태그와 협업 영향 범위를 조사해 이력을 정리하는 것이다. 광고 그룹 교체가 필요한지는 콘솔 지원 여부와 담당자 판단을 별도로 확인한다. 이력 재작성·강제push·광고 그룹 변경은 수행하지 않았다. RCR-14 전체 완료는 기존 이력 대응 결정까지 대기다.

2026-10-05 후속 사용자 지시:커밋·푸시·다음 작업 시작을 명시했으므로 신규 실제ID 없는 일반 커밋·push는 진행한다. 기존 원격 이력 비노출 목표는 여전히 미달성이며 강제push/이력재작성/검수제출/출시 승인으로 확대하지 않는다.
