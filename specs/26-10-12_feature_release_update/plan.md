# 출시 업데이트 계획

각 단계의 "승인"은 외부 상태를 바꾸므로 사용자의 명시적 지시가 있을 때만 진행한다. 실행하지 않은 단계는 완료로 표시하지 않는다.

1. [x] **출시 설정 준비(사용자)**: 이번에는 설정 파일 대신 사용자가 지난 출시와 같은 방식(활성 배너 그룹 ID를 빌드 환경변수로만 전달)으로 빌드했다. 파일을 쓰는 경우 `../local-config/ait-fridgepick/.env.release.local`에 `FRIDGEPICK_BANNER_AD_GROUP_ID`를 둔다. 기존 파일은 덮어쓰지 않는다. 값은 대화·로그·문서에 쓰지 않는다.
2. [x] **릴리스 소스 고정**: 업데이트 대상 소스 SHA를 정한다(현재 `master` `40207f7` 기준). 이후 커밋은 번들에 포함되지 않는다.
3. [x] **출시 빌드(승인 불필요, 로컬)**: `npm run build:release`. 설정이 없거나 형식이 다르면 빌드가 중단된다. 산출물 `ait-fridgepick.ait`의 크기·SHA256·deploymentId를 기록한다.
4. [x] **번들 검사**: 출시 번들에 테스트 배너 ID가 없고 실제 ID 형식(`ait.v2.live.…`)이 있는지 값을 출력하지 않고 확인한다(개수만 기록). 기본 빌드 산출물과 섞이지 않게 같은 파일명(`ait-fridgepick.ait`) 덮어쓰기 순서를 기록한다.
5. [x] **자동 검증 재실행**: `npm test`, `npm run test:scripts`, `npm run lint`, `tsc -b` (현재 `master`: 245개 통과, lint 기존 경고 1개).
6. [x] **번들 업로드(승인)**: `20261012-23` 등록·빌드 완료.: 콘솔 "버전 등록하기". 메모에 소스 SHA·출시 광고 모드·변경 요약을 적는다.
7. [~] **출시 번들 기기 확인(사용자)**: 사용자 결정으로 테스트 푸시·기기 확인을 생략한다(아래 참고).: 출시 번들은 콘솔 테스트(`isTested`) 경로가 테스트 번들과 같은지 확인한다. 실제 광고는 출시 번들에서만 확인할 수 있다. 테스트 광고용 `-22`의 기기 확인은 이미 사용자 보고로 정상이다.
   - 참고(2026-10-12 사용자 결정): 출시 번들의 테스트 푸시·기기 확인은 생략한다. 위험은 validation.md에 기록했다.
8. [ ] **앱 정보 갱신 결정(사용자)**: 미리보기 세로형 3장·주요 기능 3개를 같은 검토 요청에 포함할지 정한다. 등록 확약 5개는 사용자가 직접 체크한다.
9. [x] **검토 요청(승인)**: 번들 `20261012-23` 제출 완료(2026-10-12), 앱 정보는 변경 없어 제출하지 않음. 원래 항목:: 처음 승인 뒤에는 번들(버전) 검토 요청과 앱 정보 검토 요청이 별개다(공지 2026-10-01). 영업일 3~7일 내 이메일 안내가 표시된다(보장된 일정 아님).
10. [x] **검수 승인 후 출시(승인)**: 승인 확인 후 사용자가 출시 실행, `20261012-23` 현재 출시됨(16:28). 원래 항목:: 라이브 전환은 별도 지시로만 한다.
11. [ ] **출시 후 확인(미실행, 사용자 확인 필요)**: 첫 화면·재료 선택·추천·광고 표시, 지표(DAU) 변화, 문의·리뷰 확인.
