# 요구사항

| ID | 완료 조건 |
| --- | --- |
| RSA-01 | 정확도 평가 기준을 코드로 고정한다: 고정 조합 세트(골든 세트)와 지표(노출 후보의 평균 부족 재료 수, 상위 k개 부족 수, 준비 완료 오분류 0건, 중복·검토 안내 노출 여부)를 `getRecipeCandidates`·선택 로직의 실제 출력으로 계산하고, 현재 값을 기준선으로 기록한다. 합성 조합이며 실제 사용자 효과로 일반화하지 않는다. |
| RSA-02 | 결과 선택 순서를 개선한다: 같은 후보 풀에서 부족 재료가 적고 매칭률이 높은 메뉴가 더 자주(또는 먼저) 노출된다. 다시 뽑기는 직전 메뉴를 제외하는 기존 규칙과 "후보가 하나면 같은 메뉴 허용"을 유지하고, 준비 완료 우선·그룹 전환 동작을 바꾸지 않는다. |
| RSA-03 | 개선 효과를 RSA-01과 같은 방법으로 전후 비교한다: 노출 메뉴의 평균 부족 재료 수가 줄고, 후보 집합·60% 기준·준비 완료 판정은 변하지 않는다. 다양성(다시 뽑기로 다른 메뉴가 나오는 정도)이 정해진 허용선 아래로 떨어지지 않는다. |
| RSA-04 | 재료 매핑의 정밀도를 점검한다: 별칭 표에서 오연결 위험이 있는 항목(짧은 이름, 파생·상위어, 다른 재료와 혼동되는 표기)을 감사하고, 확인된 오류만 수정한다. 모호한 이름은 계속 보존한다. 감사는 근거(레시피 ID·원문 줄)를 남기는 표본 방식이며 전체 정확도를 보증하지 않는다. |
| RSA-05 | 원문과 추천이 어긋나는 위험을 줄인다: 이름이 같은 레시피 20개의 처리 방침, 나머지 원문 불일치 의심 항목의 추가 대조(기존 RSC-12 잔여)를 정한 범위에서 수행한다. 원문 분량·조리 순서·필수 목록은 추정 수정하지 않는다. |
| RSA-06 | 화면 표시에서 사용자가 정확도를 오해하지 않게 한다: 매칭률이 주재료 중심이라는 안내와 부족 재료 표시가 선택 순서 변경 후에도 일관된다. 새 문구는 하드 규칙(15px 이상, keep-all 등)을 따른다. |
| RSA-07 | 기존 테스트 전체와 신규 테스트(골든 세트·순서·다양성·회귀)가 통과하고 lint·기본 빌드·테스트 광고 ID 검사가 통과한다. |
| RSA-08 | 새 번들의 실기기 확인(결과 품질 체감, 다시 뽑기 동작)은 사용자 결과가 필요한 별도 단계이며 완료 전에는 로드맵을 완료로 표시하지 않는다. |
