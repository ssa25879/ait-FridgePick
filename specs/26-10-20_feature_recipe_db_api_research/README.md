# 레시피 DB·API 탐색

레시피를 더 추가하려는 요청(2026-10-20)에 대비해 사용할 수 있는 데이터 소스와 연동 방식을 조사한다.

- 브랜치: `feature/seasoning-assumption`(문서만 같은 브랜치에 둠)
- 상태: **조사 문서만 작성. 데이터 확보·코드·콘솔 변경은 하지 않았다.**
- 조사 방법: 공식 문서(앱인토스 개발자센터), 공공데이터포털 페이지, 웹 검색. 검색만으로 확정하지 못한 항목은 "미확인"으로 표시했다.

## 먼저 알아둘 것

1. **레시피를 늘리는 것만으로는 "바로 만들 수 있는 메뉴" 문제가 풀리지 않는다.** 현재 1,359개 중 1,120개(82%)는 지원하지 않는 필수 재료(육수·기름·호박 등) 때문에 어떤 냉장고로도 준비 완료가 될 수 없다. 새 레시피도 같은 방식으로 재료 매핑을 거쳐야 하고, 매핑되지 않으면 늘어난 만큼 "재료 추가가 필요한 메뉴"만 늘어난다. 양념 가정은 [별도 설계](../26-10-20_feature_seasoning_assumption/README.md)에서 다룬다.
2. 현재 구조는 **빌드 시점에 공공 자료를 정적 카탈로그로 변환**한다(`scripts/generateRecipeCatalog`). 서버·DB·실시간 API 호출이 없다. `specs/tech.md`는 백엔드·DB·외부 레시피 API를 MVP 범위에서 제외했다.

공공데이터포털 검색에서 한식 재료·조리법을 한 번에 조회하는 **새로운 오픈 API는 확인하지 못했다.** 식약처·EPIS 두 곳이 사실상 주된 공공 레시피 소스로 이미 반영되어 있다. 다른 후보는 규모가 작거나 형식이 다르다.

### 해외·상용 API (검색 기반, 모두 확인 필요)

| API | 알려진 점 | 한계 |
| --- | --- | --- |
| Spoonacular | 재료 기반 검색(`findByIngredients`)을 제공한다고 알려짐. 무료 구간 한도는 출처마다 다름(일 50~150포인트, 월 3,000~9,000건) | 영어 데이터, 한식 적합성 불명, 출처 표기와 캐시 약관 미확인 |
| TheMealDB | 무료 접근이 있으나 제3자 요약에 따르면 앱스토어 게시는 유료 구독이 필요하고 출처 표시 의무가 있음 | 약관 원문 미확인, 규모 미확인, 영어 데이터 |

두 곳 모두 한국어 재료명 매핑·번역이 필요하고 한식 커버리지가 낮을 가능성이 크다. 현재 제품(한식 중심, 한글 재료)과 맞지 않는다.

## 연동 방식 비교

| 방식 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 빌드 시점 수집 → 정적 카탈로그 (현행 확장) | 새 자료를 스크립트로 변환해 번들에 포함 | 서버·키 불필요, 오프라인, 기존 파이프라인 재사용, 비용 없음 | 번들 크기 증가(현재 JS 약 3MB), 갱신 시 새 번들·검수 필요 |
| B. 앱에서 외부 API 직접 호출 | 실행 시 공공·상용 API 호출 | 번들이 작고 데이터가 최신 | **API 키가 번들에 노출**(프록시 필요), 가용성·지연·쿼터 의존, CORS 허용 필요, 오프라인 불가 |
| C. 자체 DB + 얇은 API (예: Supabase, Cloudflare D1) | 정제한 레시피를 외부 저장소에서 제공 | 번들 없이 갱신, 검색·필터 서버 처리 가능 | 서버 운영·비용·보안 설정, mission의 "서버 없음" 원칙 변경, 개인정보 이슈는 없음 |

플랫폼 사실(공식 문서): 미니앱이 외부 서버와 통신하려면 서버의 CORS 허용 Origin에 미니앱 Origin(`https://<appName>.apps.tossmini.com`, QR 테스트는 `private-apps`)을 추가해야 한다. 앱인토스 문서는 외부 저장소로 Supabase·Firebase·Cloudflare를 예로 든다. 따라서 B·C는 기술적으로 가능하다. 다만 사용량 과금·제한은 서비스별 최신 요금제를 확인해야 한다.

## 권고

1. 지금은 **A를 유지**한다. 현재 문제(준비 완료 부족)는 양념 가정과 재료 매핑으로 해결하는 편이 레시피 추가보다 효과가 크다.
2. 데이터를 더 늘려야 한다면 **새 레시피보다 재료 매핑 보강이 먼저**다. 합성 측정에서 미지원 상위 100개를 해소하면 준비 가능 레시피가 239 → 401개가 된다(양념 가정 기준).
3. 새 소스가 필요하면 우선순위는 공공 자료의 파일 다운로드(A 방식)다. 확인된 후보는 규모가 작아(30~50건) 효과가 제한적이다.
4. C는 사용자가 직접 레시피를 추가·수정하거나 실시간 갱신이 필요해질 때 검토한다. 지금 필요한 근거는 없다.

## 미확인·다음 단계

- 위 "미확인" 표 항목의 건수·이용 조건·형식은 각 공공데이터포털 페이지를 직접 열어 확인해야 한다.
- 해외 API 약관(캐시·앱스토어 게시·출처 표기)은 공식 약관 원문 확인이 필요하다.
- 데이터를 추가하기로 정하면 기존 `scripts/generateRecipeCatalog` 입력 형식과 맞는지, 이용허락 범위, 원문 재료 매핑 비용을 먼저 평가한다.
- 사용자 결정 필요: 레시피 확대를 양념 가정·매핑 보강과 병행할지, 새 소스 확보를 별도 작업으로 둘지.
