# 개발 계획: 재료 카탈로그와 선택

## 목표

재료 선택 안내 화면을 카테고리별 로컬 재료를 선택하는 화면으로 바꾸고, 홈 왕복 중에도 선택 상태를 유지한다.

## 변경 파일 후보

- `src/types/ingredient.ts`: 재료 카테고리와 `Ingredient` 타입
- `src/data/ingredients.ts`: 28개 초기 재료 카탈로그
- `src/components/CategoryTabs.tsx`: 카테고리 전환
- `src/components/IngredientChip.tsx`: 재료 선택·해제 버튼
- `src/components/SelectedIngredientBar.tsx`: 선택 재료와 개수 요약
- `src/pages/IngredientPage.tsx`: 실제 재료 선택 화면
- `src/pages/IngredientSelectPlaceholder.tsx`: 새 화면 연결 후 사용 중단 파일 제거
- `src/App.tsx`: 선택 ID 상태를 화면 상위에서 소유하고 화면 간 전달
- `src/App.css`: 모바일 카테고리·칩·선택 요약 배치

필요성이 확인되지 않으면 새 라우터, 상태 관리 라이브러리, 데이터 저장소를 추가하지 않는다.

## 전역 제약

- 카테고리 키는 `vegetable | meat | eggDairy | carb | seasoning`이다.
- 초기 목록은 요구사항 문서의 28개 재료를 사용하고 ID는 고유한 소문자 ASCII snake_case로 고정한다.
- 선택 ID는 앱 실행 중에만 유지하며 영속 저장하지 않는다.
- 레시피, 추천 계산, 결과 화면과 다시 뽑기는 이번 계획에 포함하지 않는다.
- 기존 React 18.3.1 및 TDS Mobile 2.5.1 범위를 유지한다.

## 선행 조건

1. 작업 브랜치 `feature/ingredient-catalog-selection`을 생성했다.
2. 현재 홈 화면과 두 화면 간 로컬 상태 전환이 있다.
3. `package.json`이 React 18.3.1 및 TDS Mobile 2.5.1을 선언한다.
4. 프로젝트에 별도 테스트 러너가 없으므로 수동 시나리오와 기존 lint/build 명령으로 확인한다.

## 작은 작업 순서

### 1. 재료 모델과 로컬 카탈로그

- [x] `IngredientCategory`와 `Ingredient` 타입을 정확한 파일에 정의한다.
- [x] 카테고리 메타데이터에 키, 표시명, 순서를 한 곳에 정의한다.
- [x] 요구사항에 적힌 28개 항목을 로컬 배열로 작성한다.
- [x] 모든 ID가 고유하고 카테고리 값이 허용된 다섯 값 중 하나인지 확인한다.

확인 기준: 각 재료가 ID·한국어 이름·카테고리를 가지며 카테고리 탭에 빠짐없이 연결된다.

### 2. 카테고리 탐색과 재료 선택 UI

- [x] 현재 설치된 TDS 버전의 카테고리 탭·버튼 API를 확인한다.
- [x] `IngredientPage`에 다섯 카테고리 전환과 활성 카테고리 목록을 배치한다.
- [x] 재료 칩을 의미 있는 버튼으로 표시하고 선택 상태를 전달한다.
- [x] 선택 요약에 선택 개수와 모든 선택 재료의 이름을 표시한다.

확인 기준: 카테고리 전환은 화면에 보이는 목록만 바꾸고 기존 선택 ID에는 영향을 주지 않는다.

### 3. 상위 상태 연결

- [x] `App`에 `selectedIngredientIds: string[]` 상태와 불변 토글 함수를 둔다.
- [x] `IngredientPage`가 선택 ID, 토글 콜백, 홈 복귀 콜백을 받게 한다.
- [x] 실제 선택 화면으로 연결한 뒤 안내 전용 placeholder 파일을 제거한다.
- [x] 홈으로 갔다 돌아와 선택 ID가 그대로 복원되는지 확인한다.

확인 기준: 중복 ID가 생기지 않고 재료를 다시 누르면 그 ID만 해제된다.

### 4. 검증

- [x] `validation.md`의 카테고리, 선택·해제, 선택 요약, 화면 이동 시나리오를 수행한다.
- [x] AIT DevTools 사용자 지정 320×640 CSS px에서 가로 넘침과 잘림을 확인한다.
- [x] Tab, Enter, Space 키로 카테고리와 재료 버튼을 사용할 수 있는지 확인한다.
- [x] `npm run lint`와 `npm run build`를 실행하고 결과를 기록한다.

## 검토 초점

- 재료 칩을 반복해서 눌러도 개수가 중복 증가하지 않고 다시 해제되는가.
- 다른 카테고리 탭을 열어도 이전 선택이 요약에 남는가.
- 선택 재료가 0개일 때 빈 요약이 명확하고 오류처럼 보이지 않는가.
- 긴 한글 이름이 320 CSS px에서 칩이나 요약을 밀어내지 않는가.
- 홈 왕복 후 재료 선택은 유지되지만 앱 새로고침 후에는 초기화되는가.

## 완료 정의

- 요구사항 `ING-01`부터 `ING-08`까지 충족한다.
- 다섯 카테고리와 28개 재료를 화면에서 탐색할 수 있다.
- 다중 선택·해제와 요약이 동작하고 홈 왕복 후에도 선택이 유지된다.
- 320 CSS px 화면과 키보드 입력을 확인한다.
- lint/build가 오류 없이 끝나고 검증 결과가 문서에 기록된다.
