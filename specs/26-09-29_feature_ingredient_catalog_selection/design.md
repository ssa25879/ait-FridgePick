# 디자인: 재료 카탈로그와 선택

## 디자인 기준

홈 진입 기능에서 적용한 TDS Mobile 기준을 유지한다. 제목·본문·버튼에는 설치된 TDS 구성요소를 우선 사용하고, 이번 기능 때문에 새 UI 라이브러리나 상태 관리 라이브러리를 추가하지 않는다.

## 사용자 흐름

```text
홈
  → 재료 고르기
재료 선택
  → 카테고리 선택
  → 재료 선택·해제
  → 선택 재료와 개수 확인
  → 홈으로 이동
  → 재료 고르기로 돌아와 기존 선택 확인
```

이번 단계에서 메뉴 뽑기·결과 이동은 제공하지 않는다. 레시피와 추천 로직이 준비되는 로드맵 후속 단계에서 연결한다.

## 화면 구성

### 재료 선택 화면

1. 상단에 TDS 제목 `재료 선택`과 홈 복귀 버튼을 둔다.
2. 정해진 순서의 카테고리 탭을 표시한다: 채소, 고기, 계란·유제품, 탄수화물, 양념.
3. 처음 진입할 때 채소 카테고리를 연다.
4. 활성 카테고리의 재료를 여러 줄의 선택형 칩으로 표시한다.
5. 화면 아래 선택 요약에 전체 선택 개수와 선택한 재료 이름을 표시한다.
6. 선택 재료가 없으면 `선택한 재료 0개`를 표시한다.
7. `홈으로` 동작으로 돌아가며, 선택 목록은 유지한다.

선택 요약은 카테고리를 바꿔도 계속 보인다. 선택한 재료를 해제하려면 해당 카테고리로 이동해 칩을 다시 누른다.

## 데이터와 상태

- `Ingredient` 카탈로그는 `src/data/ingredients.ts`의 로컬 상수다.
- `IngredientCategory`와 `Ingredient` 타입은 `src/types/ingredient.ts`에 둔다.
- `selectedIngredientIds: string[]`는 `App`에서 소유한다. 화면 단위 컴포넌트가 언마운트되어도 홈 왕복 후 유지된다.
- 선택 순서는 사용자가 처음 선택한 순서를 유지한다. 이미 선택된 ID를 다시 선택하면 해당 항목만 제거한다.
- 활성 카테고리는 선택 화면의 화면 상태다. 화면에 다시 들어올 때 기본 카테고리인 채소부터 연다.
- 이 기능은 앱 실행 간 영속성이나 추천 결과 상태를 만들지 않는다.

## 컴포넌트 책임

| 컴포넌트 | 책임 |
| --- | --- |
| `IngredientPage` | 화면 배치, 활성 카테고리, 선택 요약과 홈 복귀 |
| `CategoryTabs` | 활성 재료 카테고리 전환 |
| `IngredientChip` | 재료 이름과 선택 여부 표시, 선택 토글 입력 |
| `SelectedIngredientBar` | 전체 선택 개수와 선택한 재료 이름 표시 |

`App`은 현재 화면과 선택 ID 목록을 소유하고 `IngredientPage`에 콜백과 값을 전달한다. 데이터 목록은 UI 컴포넌트 안에서 중복 정의하지 않는다.

## 반응형·접근성

- 320 CSS px 이상에서 가로 스크롤이 생기지 않도록 한다. 세로 스크롤은 허용한다.
- 카테고리 탭은 활성 상태를 보조 기술에 전달하고 키보드로 이동할 수 있어야 한다.
- 재료 칩은 의미 있는 버튼 요소와 선택 상태(`aria-pressed` 또는 TDS에서 지원하는 동등한 상태)를 제공한다.
- 선택/해제는 색상만으로 구분하지 않고, 모양 또는 텍스트 상태도 함께 사용한다.
- 긴 선택 재료 이름은 줄바꿈하며 버튼과 요약 영역을 밀어내거나 겹치지 않게 한다.

## 구현 원칙

- 기존 앱의 단순한 로컬 상태와 props 흐름을 유지한다.
- TDS Mobile 2.5.1의 탭·버튼 API를 구현 시점 공식 문서에서 확인한다. 적합한 칩 컴포넌트가 없으면 의미 있는 버튼에 TDS 토큰을 적용한다.
- 추천 로직, 결과 화면, 앱 재실행 간 저장은 다른 로드맵 단계로 둔다.
