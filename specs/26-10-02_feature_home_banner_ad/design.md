# 설계: 홈 하단 배너 광고

## 구조와 생명주기

- App 최상위에서 TossAds.initialize.isSupported()를 확인한 뒤 SDK 초기화를 한 번 수행한다. 프로젝트가 React StrictMode를 사용하므로 개발 환경의 effect 재실행에도 중복 초기화하지 않도록 앱 수명 동안 유지되는 초기화 가드를 둔다. 실제 배너를 붙이기 전에는 TossAds.attachBanner.isSupported()도 확인한다.
- 초기화 상태는 Home 화면의 배너 부착 시점에 전달한다. SDK가 준비되지 않았거나 지원되지 않는 경우 광고 슬롯을 부착하지 않는다.
- HomePage에만 배너 컴포넌트를 렌더링한다. IngredientPage와 ResultPage에는 배너 컴포넌트나 광고 SDK 호출을 추가하지 않는다.
- 배너 컴포넌트는 내부가 빈 DOM 컨테이너가 준비된 뒤 TossAds.attachBanner를 호출한다. 화면 이탈이나 언마운트 시 반환 객체의 destroy를 호출한다.
- SDK가 제공하는 배너 스타일과 이벤트를 그대로 사용한다. 광고 자체의 글꼴·색·CTA·이벤트를 임의로 변경하지 않는다.

## 홈 레이아웃

- Home 영역은 사용 가능한 화면 높이를 채우는 세로 레이아웃으로 구성한다. CTA와 배너를 아래쪽에 배치하되 배너는 일반 문서 흐름에 두고 화면을 덮는 fixed 오버레이로 사용하지 않는다. 콘텐츠가 높이를 넘으면 페이지가 세로로 스크롤된다.
- 컨테이너 너비는 safe-area padding을 포함한 화면 너비(100%), 고정형 높이는 공식 권장값인 96px로 둔다.
- 홈 CTA를 배너 위에 두고 각각 독립적으로 조작 가능하게 한다. 광고가 CTA를 대체하거나 가리지 않는다.
- 앱 루트에 이미 설정된 safe-area padding을 유지하고 하단 광고와 홈 인디케이터 사이에 공간이 남도록 확인한다.
- 광고가 CTA를 덮지 않으며 다른 화면이나 콘텐츠 위로 떠오르지 않는다.

## 광고 ID와 지원 환경

- 개발·테스트 및 기본 `build`에서는 공식 배너 테스트 ID인 ait-ad-test-banner-id를 사용한다.
- 콘솔에서 “배너 광고 1차” 지면이 ENABLED이고 groupId `[release ad ID: external local configuration]`가 발급된 것을 확인했다. `build:release`에 해당 ID를 연결하며 테스트 빌드에는 넣지 않는다.
- ID 선택은 Vite 모드로 분기한다. 모드가 `release`일 때만 실제 ID를 사용하고 그 외에는 테스트 ID를 기본값으로 쓴다.
- 공식 문서의 최소 지원 토스 앱 버전은 5.241.0이다. 초기화·부착 API의 isSupported 확인을 우선하며, 미지원 버전에서는 광고 없이 홈을 표시한다.
- 샌드박스는 광고를 지원하지 않는다. 실제 광고 렌더링은 콘솔 QR을 통해 토스 앱에서 확인한다.

## 오류 동작

- SDK 미지원, 초기화 실패, 광고 없음, 광고 렌더 실패는 로그·검증 대상으로 기록한다.
- 광고가 없어도 광고 컨테이너용 빈 프레임이나 가짜 광고를 CTA처럼 노출하지 않는다.
- 광고 오류가 React 화면 전환이나 재료 선택 기능에 영향을 주지 않아야 한다.

## 검증 범위

- SDK 초기화는 앱 세션에서 한 번만 호출되는지 확인한다.
- Home에서만 모드별 광고 ID가 부착되는지, 홈을 떠날 때 슬롯이 제거되는지 확인한다.
- 기존 홈 CTA, safe area, 320×640 화면과 앱인토스 빌드를 확인한다.
- 상세 시나리오는 [validation.md](./validation.md)를 따른다.
