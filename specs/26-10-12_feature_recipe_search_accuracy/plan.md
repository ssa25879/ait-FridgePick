# 작업 순서

선행 조건: 사용자가 [미확정 사항](./decisions.md)을 검토하고 구현 시작을 승인한다. 승인 전에는 코드를 바꾸지 않는다.

1. [ ] RSA-01 평가 세트: 골든 조합 세트와 지표 계산 코드를 만들고 현재 기준선을 `validation.md`에 기록한다(기존 임시 측정 `node_modules/.cache/rgc/acc.test.ts`가 출발점).
2. [ ] RSA-02·03 실패 테스트 먼저: 점수 함수, 구간 선택, 직전 제외, 후보가 하나일 때, 준비 완료 우선, 결정적 `random` 주입에 대한 테스트를 쓰고 실패를 확인한다.
3. [ ] RSA-02 구현: 순수 함수로 점수·구간 선택 추가, `pickRecipeCandidate` 연결. `App.tsx`의 호출부 변경은 최소화한다.
4. [ ] RSA-03 전후 비교: 노출 메뉴 평균 부족 재료·상위 k·다양성을 기록한다.
5. [ ] RSA-04 매핑 감사: 별칭 표 위험 항목 추출 → 표본 근거 확인 → 확인된 오류만 테스트 먼저 수정. 결과를 `decisions.md`에 표로 남긴다.
6. [ ] RSA-05 이름 중복 20개·나머지 의심 항목 대조(범위는 결정 후).
7. [ ] RSA-06 문구·표시 점검: 320/393px 브라우저와 하드 규칙 확인.
8. [ ] RSA-07 전체 검증: `npm test`, `npm run test:scripts`, `npm run lint`, `npm run build`, 테스트 광고 ID 검사.
9. [ ] 새 번들 준비·업로드(승인 필요) 후 RSA-08 사용자 기기 확인.
