# 개발 계획: 레시피 데이터

## 목표

로드맵 4단계 메뉴 후보 계산이 사용할 20개 로컬 레시피와 검증 가능한 타입 계약을 준비한다.

## 변경 파일

- `src/types/recipe.ts`: 레시피와 난이도 타입
- `src/data/recipes.ts`: 로컬 레시피 20개
- `src/data/recipes.test.ts`: 데이터 무결성과 재료 참조 검증
- `specs/roadmap.md`: 3단계 완료 내용과 확인 근거
- `specs/26-09-29_feature_recipe_data/*`: 기능 문서

## 전역 제약

- 레시피 수는 20~30개 범위다.
- 각 메뉴에는 필수 재료 3~6개와 조리 단계 3~5개를 둔다.
- 재료 ID는 현재 `src/data/ingredients.ts`에 있는 ID만 참조한다.
- 난이도는 `easy | normal`이며 추가 의존성은 도입하지 않는다.
- 추천 계산, UI, 앱 상태 변경은 이번 범위에 포함하지 않는다.

## 선행 조건

1. 2단계 재료 카탈로그의 28개 ID가 `src/data/ingredients.ts`에 있다.
2. Vitest가 설정되어 있고 `npm test` 명령을 사용할 수 있다.
3. 작업 브랜치는 `feature/recipe-data`다.

## 작업 순서

### 1. 모델과 로컬 카탈로그

- [x] `RecipeDifficulty`와 `Recipe` 타입을 정의한다.
- [x] 기존 카탈로그 ID만 사용해 로컬 레시피 20개를 작성한다.
- [x] 각 메뉴의 필수 재료, 선택 재료, 단계, 난이도를 확인한다.

확인 기준: 레시피 데이터가 TypeScript 컴파일을 통과하고 메뉴마다 필수 필드가 있다.

### 2. 데이터 무결성 검증

- [x] 레시피 개수와 고유 ID를 확인한다.
- [x] 필수·선택 재료 ID가 기존 재료 데이터에 있는지 확인한다.
- [x] 필수 재료 3~6개, 단계 3~5개, 난이도와 필드 누락 여부를 검사한다.
- [x] 필수·선택 재료 ID 간 중복을 확인한다.

확인 기준: `npm test`의 레시피 카탈로그 검증이 통과한다.

### 3. 프로젝트 검증 및 로드맵 반영

- [x] `npm run lint`를 실행한다.
- [x] `npm run build`를 실행한다.
- [x] 결과와 미해결 사항을 `validation.md`에 기록한다.
- [x] 3단계 완료 기준과 상태를 `specs/roadmap.md`에 반영한다.

확인 기준: 테스트, lint, TypeScript/Vite/AIT 빌드가 모두 종료 코드 0이다.

## 검토 초점

- 오탈자 때문에 존재하지 않는 재료 ID를 참조하지 않는가.
- 같은 메뉴 ID나 필수·선택 재료가 반복되지 않는가.
- 단계 문구가 비어 있거나 요구 범위를 벗어나지 않는가.
- 사용자에게 보이는 메뉴 이름과 내부 ID가 혼동되지 않는가.

## 완료 정의

- `REC-01`부터 `REC-06`까지 충족한다.
- 로컬 레시피 20개가 타입과 무결성 검증을 통과한다.
- lint/build가 오류 없이 끝나며 검증 결과가 문서화된다.
- 다음 단계인 메뉴 후보 계산을 구현하지 않은 상태로 유지한다.
