# 결정 기록: 레시피 데이터

## 확정 사항

### 1. TypeScript 로컬 데이터 사용

- 결정: JSON이나 원격 API가 아니라 `src/data/recipes.ts`에서 타입을 적용한 상수 배열을 제공한다.
- 근거: 기존 재료 카탈로그와 프로젝트 MVP 방향이 로컬 TypeScript이며, 추천 기능 전까지 별도 데이터 계층이 필요하지 않다.

### 2. 첫 카탈로그는 20개 메뉴

- 결정: 로드맵 범위인 20~30개 중 최소 기준인 20개를 작성한다.
- 근거: 다음 단계에서 매칭 로직을 검증할 만큼의 메뉴 다양성을 확보하면서 MVP 데이터 입력 범위를 제한한다.

### 3. 재료 ID는 기존 카탈로그에 한정

- 결정: 필수·선택 재료는 `src/data/ingredients.ts`의 ID만 참조한다.
- 근거: 없는 재료가 선택 재료 계산에서 항상 부족 상태가 되거나 카탈로그와 불일치하는 문제를 방지한다.

### 4. 데이터 단계와 추천 단계를 분리

- 결정: 후보 선정·점수·랜덤 추천은 구현하지 않는다.
- 근거: 로드맵 3단계의 완료 여부를 독립적으로 검증하고, 추천 규칙은 4단계에서 결정한다.

## 범위 밖 메모

기획서에 있는 60% 추천 기준은 초기 제안값이며 이번 데이터 단계에서 확정하지 않는다.
