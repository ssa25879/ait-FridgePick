# 레시피 검색 정확도 향상

사용자가 보는 결과가 "내 재료와 실제로 잘 맞는 메뉴"에 가까워지도록 추천 선택·매칭 정밀도·데이터 신뢰를 개선한다. 이 앱에는 자유 텍스트 검색이 없고, 재료 선택 → 후보 계산 → 메뉴 하나 노출이 "레시피 검색"이다. 그래서 이 문서의 "검색 정확도"는 **재료 기반 추천 정확도**를 뜻한다(범위 해석은 [결정·미확정](./decisions.md) 1번에서 확인한다).

- 브랜치: `feature/recipe-search-accuracy` (기준 `master` ca55bfa, 추천 공백 보완 병합 직후)
- 상태: **계획 문서만 작성. 구현·검증·업로드·출시는 하지 않았다.**
- 선행: [추천 공백 보완](../26-10-12_feature_recommendation_gap_coverage/README.md)(재료 125개) 완료·병합. 이번 범위는 그 위에서 "무엇을 보여줄지"와 "맞는지"를 다룬다.
- 라이브: `20261006-19`. 이 기능은 라이브에 반영되기 전이다.

## 왜 필요한가 (2026-10-12 실측, master ca55bfa)

기본 양념 11개를 갖춘 일상 조합 10개로 `getRecipeCandidates`를 계산했다(합성 조합이며 실제 사용자 효과가 아니다).

- 후보 11~39개 중 사용자가 보는 메뉴는 **후보 안에서 무작위**로 정해진다(`pickRecipeCandidate`). 준비 완료가 없으면 후보 전체에서 뽑는다.
- 무작위로 뽑을 때 평균 부족 재료는 1.8~4.1개이지만, 부족이 적은 상위 5개는 0~2개다. 같은 후보인데 "가장 맞는" 메뉴가 거의 안 뽑힌다.
- 후보의 25~78%가 부족 재료 3개 이상이다.
- 레시피 1,359개 중 원문 불일치 검토 안내가 붙은 것이 201개이고, 이름이 같은 레시피가 20개 있다.
- 후보 판정은 모두 주재료 기준(`matchBasis: main`)이며, 부족 재료 수는 점수에 반영되지 않는다.
